# Модель данных

> Статус: 🟢 актуально · Обновлено: 2026-09-22 · Владелец: olegosx

## Назначение документа

Описать сущности приложения, их поля и связи. Соответствует коду
`src/pxcontrol/engine/db/models.py` (миграции `e5cc5457ed7a` … `e3f9a2c7d514`);
соответствие закреплено тестом `test_schema_matches_models`
(autogenerate-сравнение Alembic).

## Принципы

- СУБД — **SQLite** (локальный файл), схема версионируется **Alembic**;
  миграции применяются при старте (`Database.init()`).
- **Внешние ключи проверяются**: `PRAGMA foreign_keys=ON` включается
  на каждом соединении (`Database`), политики удаления объявлены в схеме
  (миграция `c1a4b83f7e29`): удаление канала каскадом уносит его настройки
  и подписи; удаление бота или userbot-аккаунта отвязывает каналы
  (`bot_id`/`tg_account_id` → NULL); удаление поля/шаблона подписи —
  каскадом значения словаря и строки состава.
- Поля, помеченные 🔐, шифруются прозрачно (тип `EncryptedStr`, ключ —
  в системном хранилище ОС; [ADR-0009](../02-architecture/decisions/0009-config-secrets-in-db.md)).
  Несовпадение ключа (перенос БД на другую машину) даёт понятную ошибку
  `SecretDecryptionError` и не мешает запуску приложения.
- Медиа-файлы в БД не хранятся — только пути; сами файлы на диске.
- У всех таблиц, кроме `app_settings`, `community_settings`
  и `caption_template_fields`, есть `created_at`/`updated_at`.

## Сущности (текущая схема)

### `app_settings` — настройки приложения (ADR-0013)
| Поле | Тип | Назначение |
|---|---|---|
| `name` | str, PK | имя настройки (из реестра ключей) |
| `value` | JSON | значение (типизированный скаляр) |

### `community_settings` — настройки канала (ADR-0013)
| Поле | Тип | Назначение |
|---|---|---|
| `community_id` | FK→communities, PK | канал (каскадное удаление) |
| `name` | str, PK | имя настройки (из реестра ключей) |
| `value` | JSON | значение |

Хранятся только отличия от умолчаний; состав, типы и умолчания задаёт
реестр ключей (`engine/services/settings.py`). Текущие ключи канала:
`enabled` (канал активен: публикация и расписание, миграция `c8f1d29e4a35`),
`default_video_preset` (пресет обработки по умолчанию; целостность ссылки
держит сервис — вариант «а» ADR-0013), `publish_times` (список «ЧЧ:ММ»,
первое — время по умолчанию).

### `bots` — Telegram-боты (несколько; канал ссылается на своего)
| Поле | Тип | Назначение |
|---|---|---|
| `label` | str | человекочитаемое имя |
| `token` 🔐 | str | токен Bot API |
| `username` | str? | @имя бота, полученное при проверке токена (getMe); миграция `b41c7a9d2e10` |
| `paused` | bool | приостановлен человеком (ADR-0029): не публикует, статистика ботом не опрашивается; назначения сохранены; миграция `c9e4a71d5b28` |

### `tg_api_credentials` — ключ API Telegram приложения (ADR-0018)

Одна запись на приложение: пара с my.telegram.org — реквизиты
приложения, не аккаунта (с одной парой входят все userbot-аккаунты).
Правится в «Настройки → Общие».

| Поле | Тип | Назначение |
|---|---|---|
| `api_id` | int | ID приложения с my.telegram.org |
| `api_hash` 🔐 | str | hash приложения |

### `tg_accounts` — userbot-аккаунты MTProto (ADR-0007)

Только реквизиты самого аккаунта; ключ API — общий, в
`tg_api_credentials` (колонки `api_id`/`api_hash` удалены миграцией
`d8f2a61c4e93`, ADR-0018).

| Поле | Тип | Назначение |
|---|---|---|
| `label` | str? | необязательная ручная пометка («рабочий»); снимается/переназначается в любой момент; миграция `e2c7b58d4a96` |
| `phone` | str? | телефон — на него приходит код входа (для новых аккаунтов обязателен) |
| `session` 🔐 | str? | строка сессии (секрет уровня пароля), после входа |
| `username` | str? | @имя аккаунта из Telegram; актуализируется автоматически; миграция `e2c7b58d4a96` |
| `first_name` | str? | имя из Telegram (раздельно с фамилией, как отдаёт API); миграция `e2c7b58d4a96` |
| `last_name` | str? | фамилия из Telegram; миграция `e2c7b58d4a96` |
| `paused` | bool | приостановлен человеком (ADR-0029): транспорт закрыт, обращений нет; сессия, пометка и членства сохранены; миграция `c9e4a71d5b28` |

Профиль (@имя, имя, фамилия) заполняется и актуализируется автоматически:
успешный вход, активация сессий на старте, живые проверки прав
(подключение сообщества, добавление участника, перепроверка доступов).
Отображаемое имя аккаунта собирает `account_display` (сервис аккаунтов):
пометка → «Имя Фамилия» → @имя → телефон.

### `ai_credentials` — ключи провайдеров ИИ
| Поле | Тип | Назначение |
|---|---|---|
| `provider` | str | провайдер (по умолчанию `anthropic`) |
| `label` | str | имя ключа |
| `api_key` 🔐 | str | ключ API |

### `video_presets` — шаблоны обработки видео (референс makeVideo)
`name`, `trim_start`/`trim_end` (обрезка с краёв, сек; 0 — не резать;
остальные параметры — от обрезанной версии; миграция `d2b8e51c7f94`),
`fade_in`/`fade_out` (затухание на краях итога, сек; 0 — без эффекта;
миграция `b9e2c74a51d3`),
`watermark_path?`, `wm_corner/margin/opacity/scale`,
`wm_start_offset?/wm_end_offset?` (окно показа вотермарка отступами
от начала/до конца, сек; миграция `f2b8d61c3a97`), `wm_fade`
(плавность переходов, сек; миграция `a3c5e97d21b4`), `intro`,
`intro_source`, `intro_hold`, `xfade`, `cover`, `no_audio`,
`target_resolution?` (ступень разрешения — число по короткой стороне
кадра: 720/1080/1440/2160; NULL — «как в оригинале», без
масштабирования; миграция `a7c3e91b5d24` проставляет существующим
пресетам 1080 — прежний конвейер вписывал кадр в рамку FullHD),
`video_bitrate_kbps?` (NULL — «как в оригинале»; миграция
`c7d2f4a91b33`), `meta_comment?` (тег comment в метаданные файла:
«ссылка на канал — описание»; миграция `e9c2a71f4d36`),
`subdir` (подпапка внутри базовых папок видео; пустая — их корень;
при создании пресета — из его имени; миграция `d4a7c92f1b58`).
Переиспользуются между каналами. Значения по умолчанию полей заданы
в коде в одном месте — `PresetFields` (сервис видео); запись всегда
создаётся со всеми полями.

### `communities` — сообщества (каналы и группы, ADR-0021)

Вид сообщества — колонка `kind`: определяется при подключении
по сущности из API и не меняется жизнью записи; изменчивые свойства —
признак форума, название и @имя — обновляются при подключении
и перепроверке доступов.
Исполнители живут отдельной таблицей (`community_executors`, ADR-0035),
а здесь — только **назначения**, по одному на вид: userbot-аккаунт
(постинг из его сессии, приоритет по ADR-0011) и бот (запасной путь,
самостоятелен — работает по токену). Инвариант «ровно один публикатор
каждого вида» держит схема, а не дисциплина сервиса.

| Поле | Тип | Назначение |
|---|---|---|
| `title` | str | название; актуализируется перепроверкой доступов |
| `tg_chat_id` | str, unique | идентификатор чата в Telegram |
| `username` | str? | @имя, если есть; актуализируется перепроверкой (None — стало приватным) |
| `kind` | str | вид: `channel` (канал) или `group` (супергруппа); миграция `b3e7d51f9a24` |
| `forum` | bool | темы (форум) включены; обновляется перепроверками; миграция `b3e7d51f9a24` |
| `default_tg_account_id` | FK→tg_accounts?, ON DELETE SET NULL | публикатор-пользователь по умолчанию (ADR-0022; NULL — не выбран) |
| `default_bot_id` | FK→bots?, ON DELETE SET NULL | публикатор-бот по умолчанию (NULL — не назначен или бот удалён; наследник `bot_id`, переименован миграцией `b5c1e83d7a64`) |

Колонки `bot_can_edit` больше нет: право бота править **чужие** посты
(от него зависят кнопки поверх поста публикателя, ADR-0031) принадлежит
паре «сообщество + бот» и живёт в снимке прав этого бота.

### `community_executors` — исполнители сообщества (ADR-0035, миграция `b5c1e83d7a64`)

Пул исполнителей обоих видов: userbot-аккаунты и боты, строка на пару
«сообщество + исполнитель». Владелец — **ровно одна** из двух ссылок
(у пользователей и ботов свои таблицы, идентификаторы пересекаются);
тем же приёмом описан владелец операции (ADR-0030), и ключ совпадает
с владельцем дорожки шлюза — поэтому «кто состоит», «что ему можно»
и «сколько он был занят» адресуются одинаково.

Членство — **факт, а не разрешение**: строка живёт, пока её не убрал
человек. Потеря прав и выход из сообщества меняют `status`, но строку
не удаляют — иначе вместе с ней пропадало бы и назначение публикатором.
Истина живёт в Telegram: снимок стареет, и отказ сервера остаётся
последним словом.

| Поле | Тип | Назначение |
|---|---|---|
| `id` | int, PK | суррогатный ключ (пара «сообщество + исполнитель» уникальна индексами) |
| `community_id` | FK→communities, ON DELETE CASCADE | сообщество |
| `tg_account_id` | FK→tg_accounts?, ON DELETE CASCADE | исполнитель-пользователь (NULL — строка бота) |
| `bot_id` | FK→bots?, ON DELETE CASCADE | исполнитель-бот (NULL — строка пользователя) |
| `status` | str | участие: `creator` / `admin` / `member` / `restricted` / `left` / `banned` (значения `ParticipantStatus`) |
| `rights` | JSON | полный снимок прав: 17 флагов администратора и разрешения участника списками выданных имён (формат — `ExecutorRights.to_payload`) |
| `checked_at` | datetime? | когда снимали снимок; NULL — снимка не было, права перенесены миграцией из того, что подтверждала прежняя модель |

Ограничения схемы: уникальность пары «сообщество + аккаунт»
(`uq_executor_account`) и «сообщество + бот» (`uq_executor_bot`); ровно
один владелец у строки (`ck_executor_single_owner`) — строка без
владельца или с двумя бессмысленна, и проверять это лучше схемой,
чем дисциплиной вызывающих.

### `community_stats` — кэш статистики сообщества (миграции `f6b2d84c9e17`, `b8d4f2a7c6e1`)

Данные для карточек дашборда и вкладки «Обзор» (ADR-0027); наполняет
их периодический опрос движка: бот — раз в 15 минут, userbot — раз
в 6 часов (флуд-дисциплина ADR-0024). Интерфейс читает только кэш.
Сбои сети кэш не затирают. NULL — данные не получены или источник
их не отдаёт.

| Поле | Тип | Назначение |
|---|---|---|
| `community_id` | PK, FK→communities, ON DELETE CASCADE | сообщество |
| `participants` | int? | подписчики канала / участники группы |
| `online` | int? | онлайн сейчас (только группы, только userbot) |
| `scheduled_count` | int? | отложенные записи на сервере Telegram (счёт аккаунтом-умолчанием) |
| `avatar_path` | str? | файл аватара в каталоге кэша (`cache/avatars`); файл при удалении сообщества убирает движок |
| `fetched_at` | datetime? | когда кэш обновлялся любым источником («Обновлено») |
| `bot_fetched_at` | datetime? | последний проход ботом (окна :00/:15/:30/:45) |
| `full_fetched_at` | datetime? | последний полный проход userbot (окна 00/06/12/18 местного времени) |
| `can_view_stats` | bool | аккаунту доступна встроенная статистика Telegram (признак сервера) |
| `linked_chat_id` | str? | связанное сообщество в формате Bot API: чат обсуждений у канала, канал у группы |
| `tg_created_at` | datetime? | момент создания (первое сообщение сообщества; читается однократно) |
| `last_post_at` | datetime? | момент последнего сообщения в ленте |
| `deleted_found` / `deleted_removed` / `deleted_checked_at` | int? / int? / datetime? | итог последнего прохода обслуживания по удалённым аккаунтам (ADR-0026, крючок из очереди) |

### `community_stats_history` — история снимков (ADR-0027, миграция `b8d4f2a7c6e1`)

Локальная история для сообществ без встроенной статистики Telegram:
участники по дням, оценка приходов и уходов (по разности соседних
снимков — оценка снизу), онлайн по часам. Строка на каждый успешный
проход опроса; хранение 90 дней, старше убирает сам опрос. Индекс
`(community_id, at)`; удаление сообщества — каскадом.

| Поле | Тип | Назначение |
|---|---|---|
| `community_id` | FK→communities, ON DELETE CASCADE | сообщество |
| `at` | datetime | момент опроса |
| `participants` | int? | участники в момент опроса |
| `online` | int? | онлайн в момент опроса (только userbot) |

### `community_analytics` — статистика Telegram (ADR-0027, миграция `b8d4f2a7c6e1`)

Последний ответ встроенной статистики Telegram (`stats.getBroadcastStats`
/ `stats.getMegagroupStats`): одна строка на сообщество, перезаписывается
редким опросом userbot — историю Telegram держит сам. `payload` — JSON
разобранных рядов: период, пары «сейчас, раньше» (`ANALYTICS_PAIRS`:
участники, просмотры / пересылки / реакции на пост и историю,
уведомления, сообщения / читающие / пишущие), рост, приходы и уходы,
часы, ряды по дням с именами (`ANALYTICS_DAILY`), доли
(`ANALYTICS_SHARES`), недавние посты, самые активные; ключи —
имена полей `CommunityAnalytics`, отсутствующий ключ читается как пусто
(запись прежнего формата не мигрируется). Сериализация — в сервисе
статистики (`analytics_to_payload` / `analytics_from_payload`).

| Поле | Тип | Назначение |
|---|---|---|
| `community_id` | PK, FK→communities, ON DELETE CASCADE | сообщество |
| `fetched_at` | datetime | когда получен ответ |
| `payload` | JSON | разобранные ряды |

### `account_operations` — операции пользователей и ботов (ADR-0030, миграция `d7c2e94a1f63`)

Запись на каждое обращение к Telegram через дорожку шлюза: кто,
какого вида, когда началось и кончилось, чем кончилось. Владелец — ровно
одна из двух ссылок (у пользователей и ботов свои таблицы). Из строк
считаются число операций за окно (по концу), занятость (сумма
пересечений интервалов с окном — операция длиннее окна учитывается
своей частью), ошибки и флуд-лимиты. Пишется пачкой раз в десять секунд
сервисом активности; строки старше года он же убирает. Индексы —
по владельцу и концу, по концу.

| Поле | Тип | Назначение |
|---|---|---|
| `tg_account_id` | FK→tg_accounts?, ON DELETE CASCADE | пользователь-владелец (NULL — операция бота) |
| `bot_id` | FK→bots?, ON DELETE CASCADE | бот-владелец (NULL — операция пользователя) |
| `kind` | str | вид: `publish` / `interactive` / `maintenance` / `background` — приоритет дорожки |
| `started_at`, `finished_at` | datetime | интервал обращения |
| `outcome` | str | `ok` / `error` / `flood` / `cancelled` |
| `wait_s` | int | срок флуд-лимита, названный Telegram (0 — не было) |

### `publish_queue_items` — очередь отправки (ADR-0016, миграция `b7f3d92c5a41`)

Черновики, ждущие отправки: поля `PostDraft` + статус. Хранятся только
неотправленные — успешные и отменённые удаляются (истина по вышедшим
постам — сам канал, ADR-0010).

| Поле | Тип | Назначение |
|---|---|---|
| `community_id` | FK→communities, ON DELETE CASCADE | канал-получатель |
| `text` | text | текст поста или подпись |
| `media_path` | str? | путь к файлу (в папке очереди `queued`) |
| `media_kind` | str | тип вложения (`MediaKind`) |
| `when` | datetime? | желаемый момент публикации (UTC); NULL — «сейчас» |
| `rename_to` | str? | переименование при отправке |
| `topic_id` | int? | тема форума (id корневого сообщения; NULL — общая лента); миграция `c5f8a24d7b31` |
| `status` | str | `pending` / `waiting` (ждёт слота отложек) / `error` |
| `error` | text? | текст ошибки последней попытки |
| `markup` | json? | обещанная клавиатура (ADR-0031; NULL — кнопок нет); формат — `markup_to_json`; миграция `e4d1b92f7a63` |
| `markup_first` | bool | режим «кнопки важнее» (ADR-0031, п. 4): пост ждёт своей минуты здесь, а не отложкой на сервере, и уходит ботом вместе с кнопками; миграция `b2f6c94e8d17` |
| `identity_kind` | str? | лицо публикации (ADR-0036, п. 3): вид названного исполнителя (`user` / `bot`); NULL вместе с `identity_id` — от имени сообщества; миграция `c7d3f91e2b58` |
| `identity_id` | int? | id названного исполнителя в его таблице; NULL — от имени сообщества |

### `community_tasks` — задачи сообщества (ADR-0038, миграция `e3f9a2c7d514`)

Сохранённая настройка на пару «сообщество + вид» — ровно одна
(`uq_community_task_kind`). Заводится при первом обращении к виду
в сообществе с умолчаниями вида; параметры и расписание — JSON
(формат держат спецификация вида и `Schedule`). Следующий момент
запуска **хранится**, а не считается на лету: случайный интервал
вытягивается один раз, перезапуск его не сдвигает. Живёт и умирает
с сообществом (CASCADE).

| Поле | Тип | Назначение |
|---|---|---|
| `community_id` | FK→communities, ON DELETE CASCADE | сообщество |
| `kind` | str | вид: `service_messages` / `deleted_accounts` / `reactions` (значения `TaskKind`) |
| `enabled` | bool | расписание действует |
| `params` | JSON | параметры вида (`TaskSpec.params_to_payload`) |
| `schedule` | JSON | расписание (`Schedule.to_payload`): `kind` — `none` / `interval` (+ `min_minutes`, `max_minutes`) / `daily` (+ `times` списком «ЧЧ:ММ»); новая задача — `none` |
| `cursor` | JSON? | состояние вида между запусками; у реакций — `{"next": n}`, номер следующего пользователя по кругу; NULL — нет |
| `next_run_at` | datetime? | следующий запуск по расписанию; NULL — не назначен |
| `last_run_at` | datetime? | когда задача запускалась в последний раз |

### `task_runs` — журнал запусков задач (ADR-0038, миграция `e3f9a2c7d514`)

Строка на каждый запуск. Заводится **в начале** работы со значением
`running` и дописывается в конце крючком записи исхода каркаса
(ADR-0025, п. 7): падение приложения оставляет честное «начат,
не завершён». Исполнитель — ровно одна из двух ссылок видом и id
(как у операций, ADR-0030); пусто, пока не выбран. Живёт и умирает
с задачей (CASCADE); строки старше срока хранения (90 дней) убирает
планировщик. Индекс `(task_id, started_at)` — журнал читают по задаче,
новые сначала.

| Поле | Тип | Назначение |
|---|---|---|
| `task_id` | FK→community_tasks, ON DELETE CASCADE | задача |
| `trigger` | str | кто запустил: `manual` / `schedule` (`TaskTrigger`) |
| `dry_run` | bool | запуск «без изменений» (просмотр, поиск) |
| `executor_kind` | str? | вид исполнителя (`user` / `bot`); NULL с `executor_id` — не выбран |
| `executor_id` | int? | id исполнителя в его таблице |
| `started_at` | datetime | начало |
| `finished_at` | datetime? | конец; NULL — идёт или приложение упало |
| `outcome` | str | `running` / `done` / `error` / `cancelled` / `interrupted` (`RunOutcome`) |
| `report` | JSON? | отчёт вида (`TaskSpec.report_to_payload`); NULL — не построен (обрыв) |
| `events` | JSON? | события списком пар «когда (ISO), что» — не больше 500 на запуск |
| `error` | text? | причина при исходе `error` |

### `post_markups` — обещанная клавиатура (ADR-0031, миграция `e4d1b92f7a63`)

Кнопки ставит только бот и только **после** публикации. У элемента
очереди есть своя строка, поэтому его клавиатура едет колонкой
(см. выше); а у отложенной записи своей строки нет — она живёт на сервере
Telegram (ADR-0010), и обещание приходится держать отдельно. Применённое
обещание удаляется: в базе остаётся только то, чего в Telegram ещё нет.

| Поле | Тип | Назначение |
|---|---|---|
| `community_id` | FK→communities, ON DELETE CASCADE | где выйдет пост |
| `scheduled_message_id` | int? | номер отложенной записи на сервере (NULL — отложки нет) |
| `message_id` | int? | номер **вышедшего** поста: по нему повторяют неудавшуюся правку клавиатуры (NULL — пост ещё не вышел); миграция `f3a7c81d9e26`. Колонки разные намеренно: у отложки и у вышедшего поста разные номера |
| `when` | datetime? | ожидаемый момент публикации (UTC); NULL — «сейчас» |
| `match_text` | text | текст или подпись поста для **точного** опознания вышедшего поста (ADR-0031, п. 9); хранится целиком, а не хешем — по строке должно быть видно, о каком посте речь |
| `markup` | json | сама клавиатура (`markup_to_json`) |
| `attempts` | int | сколько раз пытались применить |
| `error` | text? | текст последней неудачи (кнопок нет — это исход, а не сбой поста) |

Индекс `ix_post_markups_community_when` — по сообществу и времени:
так обещания читают и дозор, и страница сообщества.

### Подписи к постам (миграция `d9f3a6e42b71`, [captions.md](../03-modules/captions.md))

Внешние ключи — с политиками удаления из миграции `c1a4b83f7e29`:
в основном каскад, кроме `parent_field_id` (SET NULL — см. ниже).

- **`caption_fields`** — пул полей канала: `community_id` FK, `name`,
  `hashtag` (оформлять значения решётками), `multiple` (несколько значений),
  `show_name` (вставлять имя поля в подпись «Имя: значения»; выключено —
  только значения; миграция `d6a9c48e2f57`, по умолчанию включено),
  `parent_field_id?` FK→caption_fields, ON DELETE SET NULL — поле, внутри
  значений которого живёт словарь этого поля (миграция `a8e4c73b9d52`);
  NULL — поле независимое.
- **`caption_values`** — словарь значений поля: `field_id` FK, `value`,
  `parent_value_id?` FK→caption_values, ON DELETE CASCADE — значение
  родительского словаря, внутри которого живёт это значение (персонаж
  внутри тайтла); NULL — привязки нет. Словарь общий для всех шаблонов
  канала. Удаление родительского значения уносит зависимые каскадом.
- **`caption_templates`** — именованные шаблоны: `community_id` FK, `name`,
  `last_used_at?` (для предвыбора в диалоге), `filename_pattern?` —
  шаблон имени файла при отправке (миграция `e7a1c94f5d28`).
- **`caption_template_fields`** — состав шаблона: `template_id` FK,
  `field_id` FK, `position`, `enabled`. Без полей времени.

## Отложено сознательно (YAGNI)

`media`, `sources`, `generation_jobs` — добавляются миграциями вместе
с соответствующими функциями (решение от 03.07.2026).

Таблицы `posts` **нет намеренно** (ADR-0010): источник истины по вышедшим
постам — сам канал; отложенные читаются из Telegram. В БД — конфигурация
и очередь ещё не отправленного (`publish_queue_items`, ADR-0016).

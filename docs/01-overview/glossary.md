## Назначение документа

Единый список терминов проекта, чтобы все (люди и ассистенты) понимали

## Термины (заполнять по мере появления)

| Термин | Расшифровка / определение |
|---|---|
| **Bot API** | Официальный HTTP-интерфейс Telegram для ботов. В приложении — запасной путь публикации (до 50 МБ, только «сейчас», ADR-0011) и служебные проверки. |
| **MTProto** | Низкоуровневый протокол Telegram для клиентов (userbot). Используется как второй транспорт наряду с Bot API — для чтения/парсинга каналов и опц. планирования (см. ADR-0007). Работает на отдельном аккаунте. |
| **userbot** | Автоматизация от имени пользовательского аккаунта Telegram (через MTProto), а не бота. Даёт чтение чужих каналов, но несёт риск блокировки аккаунта. |
| **Пользователь** | Userbot-аккаунт MTProto как сущность приложения (ADR-0029): раздел «Пользователи и боты», карточка с состоянием (подключён / нет связи / вход не выполнен / приостановлен), участием в сообществах и действиями. В коде — `TgAccount`. |
| **Активность** | Учёт обращений исполнителя к Telegram (ADR-0030): запись на каждую операцию дорожки (вид, интервал, исход) в `account_operations`, год хранения. На карточке — операции за сутки, занятость (доля времени окна, когда дорожка была занята), ошибки, флуд-лимиты и живое состояние дорожки. |
| **Приостановка** | Состояние пользователя или бота (`paused`, ADR-0029): приложение его не использует ни для чего, но помнит целиком — сессию, пометку, членства, назначения. Посты сообщества, чей публикатор приостановлен, ждут в очереди отправки. Снимается только человеком. |
| **session string** | Строка сессии MTProto — по силе равна паролю аккаунта; хранится зашифрованно, не попадает в код и логи. |
| **Сообщество** | Центральная сущность приложения (`Community`, ADR-0021): подключённый канал или группа Telegram. Вид (`kind`) определяется при подключении; публикаторы — userbot и/или бот. |
| **Канал** | Вид сообщества: канал-вещалка. Публикует администратор с правом `post_messages`. |
| **Группа** | Вид сообщества: супергруппа. Публикует любой участник, не ограниченный в отправке; малые (не супер-) группы не подключаются. |
| **Тема форума** | Отдельная лента в группе с включёнными темами; адресуется id корневого сообщения (`topic_id`). «General» (id 1) — общая лента. Список тем читает только userbot; в закрытую тему пишет только админ. |
| **Исполнитель сообщества** | Пользователь или бот, работающий в сообществе (`community_executors`, ADR-0035). Строка — факт: она живёт, пока её не убрал человек, и несёт снимок прав из зондов — участие (`ParticipantStatus`: владелец, админ, участник, ограничен, не состоит, исключён) и полный перечень прав (17 флагов администратора и разрешения участника, включая реакции). Пул — фундамент соцактивности и распределения нагрузки. |
| **Ввод исполнителя** | Операция приложения (ADR-0035): завести исполнителя в сообществе — вступив по @имени или ссылке-приглашению, приглашением силами пула либо назначением администратором (так в канал попадает бот). Только по явному действию человека, никогда в фоне; ссылок приложение не создаёт, а читает существующую. |
| **Публикатор по умолчанию** | Назначение сообщества, по одному на вид: `default_tg_account_id` (пользователь, ADR-0022) и `default_bot_id` (бот). Права — знание Telegram, назначение — решение человека; назначить можно и того, кто сейчас публиковать не может. |
| **Задача сообщества** | Сохранённая настройка сообщества (ADR-0038, `community_tasks`): вид (служебные записи, удалённые аккаунты, реакции — ADR-0039; дальше — приём заявок), параметры, расписание, включена ли. Одна на вид в сообществе. Вкладка «Задачи» страницы сообщества. |
| **Запуск задачи** | Одно выполнение задачи (`task_runs`): кто запустил — человек или расписание, чьими руками шла работа, когда, чем кончилось (готово · ошибка · отменено · прервано остановкой), отчёт и события. Журнал запусков — мини-лог задачи в сообществе. Запуск «без изменений» только смотрит и считает. |
| **Задание** | Элемент очереди каркаса заданий движка (ADR-0025): статус, прогресс, отмена, повтор. Несёт запуск задачи, пока тот выполняется; живёт в памяти, перезапуск не переживает. |
| **Пост** | Единица контента для публикации (текст, медиа, кнопки). |
| **Источник** | Внешний поставщик контента: другой канал, сайт или RSS-лента. |
| **Очередь модерации** | Список заготовок контента, ожидающих одобрения человеком. |
| **Планировщик** | Своего компонента нет (ADR-0010): отложенные записи хранит и публикует сервер Telegram; экран «Отложено» раздела «Публикация» читает их из сообществ, правит (текст и время), публикует «сейчас» и удаляет на сервере (ADR-0028, ADR-0032). |
| **Отложенная запись** | Пост, который уже принял сервер Telegram и опубликует сам в назначенное время — даже при выключенном приложении. Отличать от поста в **очереди отправки**: тот ждёт слота или отправки в приложении и без запущенного приложения не уйдёт. |
| **Очередь отправки** | Персистентная очередь публикации (ADR-0016, таблица `publish_queue_items`): посты уходят последовательно, с прогрессом и отменой; сверх лимита 100 отложек — ждут слота. |
| **Пресет** | Сохранённый набор параметров обработки видео (обрезка, вотермарк, заставка, битрейт, подпапка). |
| **Подпись** | Текст к посту, собираемый по шаблону из полей со словарями («**название** + Поле: #значения»). |
| **Отложенный постинг** | Публикация поста в будущем по расписанию, а не сразу. |
| **Рерайт** | Переписывание исходного материала перед публикацией (часто с помощью ИИ). |
| **ADR** | Architecture Decision Record — запись о принятом архитектурном решении. |

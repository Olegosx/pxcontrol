# API движка (внутренний интерфейс)

> Статус: 🟢 готов · Обновлено: 2026-09-15 · Владелец: olegosx

## Назначение документа

Описать программный интерфейс **движка** (engine) — набор операций, которые
интерфейс на PySide6 вызывает напрямую в процессе. Это десктопное приложение
([ADR-0006](../02-architecture/decisions/0006-desktop-pyside6.md)), поэтому
HTTP/REST API не используется; «API» здесь — публичные Python-сервисы движка.

> Если в будущем понадобится удалённое управление, этот же движок можно
> обернуть в HTTP API (тогда вернётся вопрос FastAPI). Сейчас — вне рамок.

## Сервисы движка (реализованы)

| Сервис | Назначение |
|---|---|
| `AccountsService` | боты (проверка токена, диагностика, число сообществ-назначений), ключ API Telegram приложения (`get_tg_api`/`set_tg_api` — одна запись, ADR-0018), userbot-аккаунты (вход: код/2FA; активация всех по сохранённым сессиям — `activate_stored_userbots`, ADR-0019; участие и число сообществ-умолчаний в DTO, признак живого соединения), приостановка и возобновление (`set_tg_account_paused` / `set_bot_paused`, ADR-0029), пометка и название (`set_account_label` — пусто снимает, `set_bot_label` — обязательно), ключи ИИ |
| `CommunitiesService` | подключение каналов (userbot — с явным выбором аккаунта, или бот), публикаторы — членствами (`add_member`/`set_default`/`remove_member`, ADR-0022; обратная сторона для страницы аккаунта — `communities_of_account` с ролью и умолчанием, `communities_of_bot`) и бот (`assign_bot`/`unassign_bot`), доступы (перепроверка меняет привязку userbot только по подтверждённому ответу Telegram), список, удаление (зависимые строки — каскадами БД) |
| `PostsService` | пределы длины текста сообщества (`text_limits`, `check_draft_limits`: 4096/1024, у Premium-публикатора 8192/4096); публикация `PostDraft` по возможностям канала: userbot в приоритете — из сессии привязанного аккаунта (ADR-0019; лимит 2000/4000 МиБ по Premium этого аккаунта), бот — запасной; выключенное сообщество и сообщество без публикатора получают отказ класса `PostNotReadyError` (поправимо человеком — очередь по нему ждёт, а не хоронит пост); отложки — сервер Telegram; чтение отложенных — аккаунтом каждого канала, ошибки по-канально; `list_scheduled(community_id)` — по одному сообществу для вкладки «Отложено» (ADR-0010, ADR-0011); маршрут выбирается лестницей `publish_route` и определяет пределы (у бота подписки не бывает); исход передачи — `PublishOutcome` (номер поста и, если кнопки не поставились, причина: пост при этом опубликован); действия над отложенными на сервере тем аккаунтом, чьим чтением запись попала в список (`ScheduledRef`): `scheduled_draft` (запись целиком с сервера и предел текста по аккаунту), `edit_scheduled` (текст и время; проверки те же, что у постановки: непустой текст без вложения, предел длины, время не ближе минуты), `send_scheduled_now`, `delete_scheduled`; исчезнувшая запись — `ScheduledGoneError`; судьбу обещанных кнопок сообщают крючки `markup_moved` / `markup_gone` (правка уводит обещание за собой, удаление снимает — связку собирает движок) |
| `VideoService` | пресеты обработки, запуск подготовки видео (чистый модуль `engine/video/`), действующие папки видео (`dirs_for`, `processed_dir_for_channel`), готовые видео подпапки — рекурсивно, включая подпапки пакетов (`list_processed`, `delete_processed`), сканирование папки исходников с длительностью (`scan_sources`), список готовой папки для пакета отправки (`scan_ready`), рекомендация битрейта (`bitrate_advice`) |
| `JobQueue` (`engine/jobs.py`) | общий каркас заданий (ADR-0025): жизненный цикл (`JobStatus`), последовательный воркер, прогресс, отмена (мягкая флагом и жёсткая отменой задачи), повтор, снятие с показа, кооперативная остановка. Предметные исходы переводит сам исполнитель; персистентность — дело конкретной очереди |
| `ProcessingQueue` | очередь обработки видео: последовательное кодирование одиночных файлов и пакетов, авто-битрейт под лимит Telegram, прогресс, отмена, повтор после ошибки, копии выбранных кадров заставки (`stash_frame`) (ADR-0014) |
| `ActivityService` | учёт активности пользователей и ботов (ADR-0030): сброс записей операций из буфера шлюза в `account_operations` пачкой (`flush`, периодическая задача `start`/`shutdown`), уборка старше года (`prune`), снимок для интерфейса (`snapshot` — живое состояние дорожек и окна час / сутки / неделя по каждому владельцу; занятость — пересечением интервалов, чистая `window_stats`), история одного владельца для графиков (`history` — часы суток за 7 дней, занятость и флуд-лимиты по местным дням за 30, виды; чистая `history_stats`) |
| `CommunityStatsService` | кэш статистики сообществ и периодический опрос (ADR-0027): `snapshot` — снимок для дашборда, `overview` — снимок «Обзора» (числа, ряды, справка, источник рядов), `refresh_due` — проход по «должникам» (бот раз в 15 минут, userbot раз в 6 часов), `record_members_report` — крючок итога обслуживания, `start_polling`/`shutdown` — периодическая задача движка |
| `MaintenanceService` | обслуживание сообществ (ADR-0026): просмотр служебных записей по видам (`scan_service_messages`) и чистка выбранных (`clean_service_messages`) — с глубиной просмотра и потолком удаления за проход; очередь заданий на общем каркасе, только userbot, право удалять проверяется живым зондом до постановки |
| `CaptionsService` | поля со словарями, шаблоны подписей, сборка текста и имени файла |
| `MarkupsService` | обещанные клавиатуры и дозор, который их ставит (ADR-0031): `start_polling`/`shutdown` — периодическая задача движка (раз в минуту), `apply_due` — один проход: дождаться времени публикации, опознать вышедший пост чтением истории (точное совпадение текста и даты; двусмысленность = «не нашлось»), поставить кнопки ботом, снять обещание; флуд прекращает проход, пять неудач отпускают обещание, приостановленный бот — повод подождать, а не тратить попытку. Хранение: `promise` (с проверкой пределов на входе — в базу не попадает то, что Telegram обрежет молча), `pending` (все или по сообществу, в порядке публикации), `reschedule` (перенос времени обещание не рвёт), `fail` (попытка не удалась — обещание остаётся), `retarget` (обещание едет за правкой отложки — время и текст), `promised_ids` (каким отложкам сообщества обещаны кнопки — для пометки на вкладке «Отложено»), `drop` / `drop_scheduled` (применено или отложка исчезла) |
| `PublishQueue` | персистентная очередь отправки: последовательная публикация, прогресс, отмена, повтор после ошибки; ожидание слота отложек (лимит Telegram — 100/канал) с проверкой раз в N минут (ADR-0016); пост в режиме «кнопки важнее» (ADR-0031, п. 4) слота не занимает — он ждёт свою минуту и уходит ботом, дозор просыпается к его сроку; временные состояния — не ошибка: нет связи с Telegram → пауза и повтор, сообщество выключено или без публикатора → ожидание до его возвращения (`PostsService.publish_blocker` — одна точка правды для подготовки и дозора слотов); атомарная постановка пакета черновиков (`enqueue_many`, ADR-0015); пост вышел без кнопок — пометка на карточке и сохранённое обещание (ADR-0031), а не ошибка элемента: повтор опубликовал бы пост второй раз; правка неотправленного элемента — чтение черновика (`get_draft`) и замена его целиком (`edit`: текст, вложение, тема, время; канал неизменен, файлы ездят по правилам ADR-0016) |
| `publish_route` | чистая лестница выбора маршрута (ADR-0031): `choose_route` (кнопок нет → публикатор; кнопки и файл по силам боту → бот отправляет сам; кнопки и крупный файл → публикатор отправил, бот дорисовал) и `markup_blocker` — одна причина «почему кнопки недоступны» на движок и интерфейс. Там же `PublishCapabilities` и `publish_capabilities` |
| `schedule_plan` | чистые функции раскладки времени пакета отправки (`plan_times`: по временам канала / каждый день / раз в N дней / каждые N часов / «сейчас», ADR-0015) |
| `SettingsService` | настройки приложения и каналов: реестр ключей, кэш, провайдер ffmpeg (ADR-0013); несколько настроек одной транзакцией — `set_many` / `set_for_many` (честная плашка «Сохранено» в UI) |

Каждый сервис объявляет узкий протокол нужной ему части шлюза Telegram
(разделение интерфейсов) — тесты подменяют только его.

## Появятся позже

`SourcesService` (источники), `QueueService` (модерация),
`GenerationService` (ИИ) — по дорожной карте.

# Схемы данных (типы границы движка)

> Статус: 🟢 готов · Обновлено: 2026-09-15 · Владелец: olegosx

## Назначение документа

Описать форматы данных движка — структуры, которыми оперируют его сервисы
и которые показывает интерфейс.

## Как реализовано

Все типы границы — **неизменяемые датаклассы** (`@dataclass(frozen=True)`),
а не Pydantic-модели: данные рождаются внутри приложения (БД, Telegram),
внешнего непроверенного ввода на этой границе нет, поэтому валидация
Pydantic не нужна, а неизменяемость защищает от случайных правок при
передаче между потоками (интерфейс ↔ движок). Pydantic используется
в одном месте — bootstrap-настройки `pxcontrol.config.Settings`
(разбор `.env`, см. [configuration.md](../06-config/configuration.md)).

Соглашение об именах: `*Dto` — снимок для показа в интерфейсе;
остальные имена — входные сущности и внутренние типы границы.

## Типы по слоям

### Сервисы (`engine/services/*`) — то, что видит интерфейс

| Тип | Модуль | Роль |
| --- | --- | --- |
| `BotDto`, `TgAccountDto`, `TgApiDto`, `AiKeyDto` | `accounts.py` | аккаунты: боты (`paused`, `publisher_of`), userbot (`connected`, `paused`, `memberships`, `publisher_of` — ADR-0029), ключ API приложения (ADR-0018), ключи ИИ |
| `CommunityDto`, `CommunityAccess` | `communities.py` | канал и итог перепроверки доступов; `default_account_paused`/`bot_paused` и вычисляемое `publisher_paused` (ADR-0029); `bot_can_edit` — право бота править чужие посты (ADR-0031) |
| `OwnerActivityDto`, `WindowStats`, `LiveDto` | `activity.py` | активность владельца (ADR-0030): живое состояние дорожки и окна час / сутки / неделя — операции по видам, занятость, ошибки, флуд-лимиты |
| `ActivityHistoryDto` | `activity.py` | история для графиков страницы аккаунта: часы суток, занятость и флуд-лимиты по дням, виды операций |
| `AccountMembershipDto` | `communities.py` | сообщество глазами аккаунта: снимок, роль, признак умолчания (страница аккаунта) |
| `PollDraft` | `telegram/poll.py` | опрос поста (ADR-0033, C5): вопрос, варианты, анонимность, множественный выбор, викторина с правильным ответом и пояснением. Правила и пределы — `validate_poll` (вопрос 1–300, 2–12 вариантов по 1–100, пояснение 0–200); хранение — колонка `poll` (миграция `a1f7d24c8e93`). Опрос исключает текст и файлы: у Telegram это самостоятельное вложение |
| `MediaFile` | `posts.py` | один файл поста: путь, вид (`MediaKind`) и новое имя при отправке. Пост держит их **списком** (`PostDraft.media`): пусто — текстовый, один — обычное вложение, несколько — альбом одной записью (ADR-0033, C4; правила — `album_blocker`, хранение — колонка `media`, миграция `e7c3a94b2d68`) |
| `PostDraft` | `posts.py` | черновик публикации — единый вход для всех типов контента; `media` — список файлов (см. `MediaFile`); `markup` — клавиатура под постом (ADR-0031), её наличие влияет на выбор маршрута отправки; `markup_first` — режим «кнопки важнее» у отложенного поста; `entities` — разметка текста (ADR-0033): пусто — обычный текст, и транспорт разбирает строку по-старому |
| `RichText`, `TextEntity`, `TextStyle` | `telegram/rich_text.py` | размеченный текст поста: видимый текст и сущности со смещениями в кодовых единицах UTF-16 (ADR-0033). Виды: жирный, курсив, подчёркнутый, зачёркнутый, `code`, `pre`, ссылка с подписью, спойлер, цитата и раскрывающаяся цитата. Правила — `validate_rich_text` (границы, перекрытия, схема адреса), хранение — `rich_to_json`/`rich_from_json`, «разметка живёт со своим текстом» — `keep_entities` |
| `PublishCapabilities` | `publish_route.py` | возможности сообщества (`markup_edit` — бот может дорисовать кнопки к посту публикателя, ADR-0031) |
| `PublishRoute`, `PublishOutcome` | `publish_route.py`, `posts.py` | каким путём уходит пост (публикатор / бот / «публикатор отправил — бот дорисовал») и чем закончилась передача (номер поста, причина отсутствия кнопок) |
| `ScheduledPostDto` | `posts.py` | отложенная запись из Telegram (с адресом `ScheduledRef`: сообщество, аккаунт-читатель, id записи в очереди отложенных) |
| `ScheduledRef`, `ScheduledDraft` | `posts.py` | адрес отложенной записи для действий над ней; запись целиком для формы правки (текст, время, вид вложения, тема, предел текста по аккаунту) |
| `PromisedMarkupDto` | `markups.py` | обещанная клавиатура поста, которого у нас нет (отложка на сервере): сообщество, номер отложки, время, текст для опознания, сама клавиатура, число попыток и последняя неудача (ADR-0031) |
| `QueueItemDto` | `publish_queue.py` | элемент очереди отправки (статус — общий `JobStatus`) |
| `PresetDto`, `PresetFields`, `FrameCandidate` | `video.py` | пресет обработки видео и кадры-кандидаты |
| `BitrateAdvice` | `video.py` | рекомендация битрейта для исходника больше лимита Telegram |
| `VideoFile`, `ProcessedListing` | `video.py` | видеофайл на диске (имя, путь, размер, дата) и содержимое подпапки результатов. Один тип на список готовых видео и на источник пакетной отправки (`scan_ready`/`ready_from_paths`, ADR-0015) |
| `FoundVideo` | `video.py` | найденное при сканировании исходников — с данными пробы ffprobe (длительность, размер кадра) |
| `VideoDirs`, `IntroSourceKind` | `video.py` | действующие папки видео; вид источника кадра заставки |
| `ProcessingRequest` | `video_queue.py` | заявка очереди обработки: файл со своими параметрами (ADR-0014) |
| `VideoItemDto` | `video_queue.py` | элемент очереди обработки (статус — общий `JobStatus`) |
| `JobStatus` | `jobs.py` | состояние задания любой очереди движка (ADR-0025) |
| `SchedulePlan`, `PlanKind` | `schedule_plan.py` | раскладка времени пакета отправки: стратегия и параметры (ADR-0015) |
| `MaintenanceItemDto`, `ServiceReport`, `MembersReport`, `MaintenanceTarget` | `maintenance.py` | задание обслуживания, итоги по служебным записям и по участникам (ADR-0026) |
| `FieldDto`, `TemplateDto`, `TemplateFieldDto`, `CaptionLine` | `captions.py` | поля со словарями и шаблоны подписей |
| `ValueDto` | `captions.py` | значение словаря поля (с привязкой к родительскому значению) |

### Телеграм-слой (`engine/telegram/types.py`) — граница «сервисы → транспорты»

| Тип | Роль |
| --- | --- |
| `BotRef` | адрес бота для бот-операций: id и токен (токен вне `repr`); по id — дорожка и учёт (ADR-0030) |
| `LaneOwner`, `OperationRecord`, `LaneLiveState` (`lane.py`) | владелец дорожки (пользователь или бот), запись операции с исходом, живое состояние дорожки (ADR-0030) |
| `MediaKind` | тип вложения поста (текст/фото/видео/аудио/файл; `OTHER` — вложение, которого приложение не создаёт, а только читает в отложенных: опрос, геопозиция — признак `creatable`) |
| `CommunityInfo` | сообщество, проверенное любым транспортом (бот или userbot); несёт `rights` — полный снимок прав **проверявшего** исполнителя (ADR-0035) |
| `ExecutorRights`, `ParticipantStatus`, `AdminRights`, `MemberRights` (`rights.py`) | снимок прав исполнителя в сообществе: как участвует, что выдано администратору, что можно участнику (реакции в том числе). Складывают его переводчики обоих транспортов — `userbot_rights` и `bot_rights`; хранение — `to_payload`/`from_payload` (ADR-0035) |
| `OutgoingPost` | исходящий пост для транспорта (несёт разметку текста и настройки превью) |
| `LinkPreview` | превью ссылки у текстового поста: выключить, крупное, над текстом, адрес (ADR-0033, C3); хранение — `preview_to_json`/`preview_from_json` |
| `PostButton`, `PostMarkup`, `ButtonKind` (`markup.py`) | клавиатура под постом и её виды кнопок (ссылка, «скопировать текст»); там же пределы Telegram (8 кнопок в ряду, 100 рядов, 128 символов подписи — вычислены опытом, сервер обрезает их молча), проверка `validate_markup` и перевод в/из JSON для колонок БД (ADR-0031) |
| `ScheduledMessage` | отложенная запись, прочитанная из Telegram: id в очереди отложенных, текст, время, вид вложения, тема форума |
| `ServiceMessageKind`, `ServiceMessageInfo`, `ServiceMessagesPage` | вид служебной записи, сама запись и страница истории (ADR-0026) |
| `ParticipantsPage` | страница списка участников с удалёнными аккаунтами (ADR-0026) |

### Видео-конвейер (`engine/video/*`) — чистый модуль без Telegram

| Тип | Модуль | Роль |
| --- | --- | --- |
| `ProcessingOptions` | `pipeline.py` | полный набор параметров обработки |
| `WatermarkOptions`, `FilterGraph` | `filtergraph.py` | вотермарк и собранный граф фильтров ffmpeg |
| `VideoInfo` | `probe.py` | сведения об исходнике (ffprobe) |

## Правило

Типы границы не равны напрямую таблицам БД: внутренняя модель хранения
описана отдельно в [data-model.md](../05-data/data-model.md). Здесь — то,
что видят интерфейс и транспорты. Сырые объекты внешних библиотек
(Telethon, aiogram, JSON ffprobe) через границу не проходят —
транспорты переводят их в перечисленные типы.

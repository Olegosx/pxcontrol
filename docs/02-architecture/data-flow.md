# Поток данных

> Статус: 🟡 черновик (потоки A и заглушки B–D) · Обновлено: 2026-08-15 · Владелец: olegosx

## Назначение документа

Показать путь контента от появления до публикации в канале — для каждого
из четырёх источников наполнения. Это помогает увидеть, где данные
создаются, хранятся, проверяются и отправляются.

## Потоки (заполнить деталями)

### Поток A. Ручной пост (ADR-0010: истина — канал, БД постов нет; ADR-0011/0012)
```
«Сейчас»:    Пользователь → Интерфейс → Очередь отправки (в движке)
   → userbot (MTProto; запасной путь — бот, Bot API, ≤50 МБ) → Канал
Отложенный:  Пользователь → Интерфейс → Очередь отправки → userbot
   (schedule_date) → отложенная запись В КАНАЛЕ → публикует сервер Telegram
```
Очередь (ADR-0012) отправляет посты последовательно, с прогрессом
загрузки и отменой; живёт в памяти движка.

Пакетный вход в тот же поток (ADR-0015): готовая папка → черновики
построчно (подписи по общему шаблону, раскладка времени стратегиями,
правка) → атомарная постановка пакета в ту же очередь отправки —
дальше всё как выше, по одному посту.

### Поток B. Генерация ИИ
```
Пользователь (тема, стиль) → Движок (фоновый поток) → Провайдер ИИ
   → черновик в БД → правка пользователем → расписание → публикация
```

### Поток C. Парсинг источника
```
Движок (по таймеру) → Источник (сайт/RSS/канал через MTProto) → нормализация
   → (опц. рерайт ИИ) → Очередь модерации (БД)
```

### Поток D. Модерация очереди
```
Пользователь → Интерфейс → Очередь модерации → одобрение
   → публикация как в потоке A («сейчас» или отложенно)
```

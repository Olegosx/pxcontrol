# ADR-0042. Пресеты подписи: название — поле, разбор имени файла — у поля

> Статус: accepted
> Дата: 2026-09-25 · Автор: olegosx
>
> Уточняет [ADR-0015](0015-batch-publishing.md) (п. 4 — подписи пакета)
> и [ADR-0023](0023-work-windows-and-question-dialogs.md) (перечень
> рабочих окон: окна «Поля подписи…» больше нет). Опирается
> на [ADR-0033](0033-rich-text-entities.md) (разметка сущностями)
> и [ADR-0013](0013-settings-storage.md) (реестр настроек — из него
> уходит ключ `title_parse_rules`).

## Контекст

Подпись к посту собиралась по **шаблону подписи** — именованному
набору полей сообщества со словарями. Настройка полей и шаблонов жила
в отдельном рабочем окне «Поля подписи…», которое открывалось
с «Публикации». К сентябрю 2026 в этой модели накопились три перекоса:

- **Название ролика было особой сущностью, а не полем.** Строка ввода
  в окне сборки, отдельный аргумент функции сборки (он всегда шёл
  первой строкой жирным) и отдельный плейсхолдер `{video}` в шаблоне
  имени файла. Три особых случая на одно значение — и ни одного
  способа сделать название не первым, не жирным или вовсе не выводить.
- **Разбор имени файла давал только название.** Цепочка замен
  по регулярным выражениям (`TitleParseRules`) хранилась настройкой
  сообщества `title_parse_rules` и правилась на экране «Пакет». Имя
  файла вида `11.12.2014 627563 Bruce Lee, Jan Clod Van Dam, Ded Morozz
  (Prosto Film)` несёт больше одного значения — тайтл и состав, — но
  разложить его по полям было нечем.
- **Настройка подписей жила не там, где сообщество.** Поля и шаблоны —
  свойство сообщества, а открывались они с «Публикации» отдельным
  окном, в стороне от вкладки «Настройки» страницы сообщества.

## Решение

1. **Шаблоны подписи становятся пресетами** — тем именем, которым их
   зовёт владелец. Переименование сквозное: интерфейс, документы, код
   (`CaptionPreset`, `CaptionPresetDto`) и схема (`caption_presets`,
   `caption_preset_fields`, колонка `preset_id`). Название DTO
   начинается с `Caption`, потому что `PresetDto` уже занят пресетами
   обработки видео.
2. **Название ролика — обычное поле.** У оформления поля появляется
   признак «жирным» (`caption_fields.bold`); сборка подписи
   (`build_caption(lines)`) выделяет жирным любую строку с этим
   признаком, сущностью разметки со смещением в UTF-16. Встроенного
   плейсхолдера `{video}` больше нет: название подставляется как любое
   поле — `{Video}`.
3. **Правило разбора имени файла — у строки состава пресета**
   (`caption_preset_fields.source_rule`, JSON; NULL — значение вводит
   человек). Одно и то же поле в разных пресетах разбирается
   по-разному, поэтому правило не у поля сообщества. Правило
   (`SourceRule`) применяется к имени без расширения и суффикса
   конвейера (`filename_source`) по шагам:
   - **извлечение** — поиск выражением; значение — группа `value`,
     иначе первая группа, иначе всё совпадение; пустое выражение —
     имя целиком; **нет совпадения — нет значения**;
   - **очистка** — прежняя цепочка замен «что найти → на что заменить»;
   - **разделение** на значения по выражению-разделителю (только у поля
     с несколькими значениями, по умолчанию запятая);
   - **регистр** каждого значения, схлопывание пробелов, отсев пустых
     и повторов.
   Битая часть правила при разборе пропускается со следом в журнале;
   сохранить битое правило нельзя — проверка `check_rule` общая для
   экрана и движка.
4. **Настройка — на вкладке «Настройки» сообщества.** Блок «Пресеты
   подписи»: строки пресетов и «Создать пресет»; клик открывает экран
   пресета в той же вкладке (строка пути «Настройки › пресет»), как
   настройка задачи открывается из обзора задач. На экране — имя,
   образец имени файла для живого предпросмотра, поля по порядку
   (оформление, связь «внутри: …», правило разбора и его результат
   на образце), шаблон имени файла, итоговые подпись и имя файла.
   Сохранение одно на весь экран — одной записью движка
   (`save_preset`: состав, правила и правки оформления полей вместе).
   Сразу выполняется только то, что меняет пул полей: новое поле
   заводится, удаление поля из сообщества — с подтверждением и перечнем
   пресетов, из которых оно уйдёт. Словарь правится в прежнем рабочем
   окне. Уход с несохранёнными правками — через вопрос «Сохранить /
   Не сохранять / Отмена».
5. **Страница сообщества узнаёт тела с правками по общему признаку**
   `UnsavedChanges` (свойство `dirty` и метод `leave`), а не по классу:
   так устроены «Задачи» и «Настройки», и вопрос при уходе задаётся
   каждому телу с правками по очереди.
6. **Сборка подписи.** Окно сборки без строки названия: поля с правилом
   заполняются из имени первого файла поста (значение из словаря
   отмечается пилюлей, новое вписывается строкой) и правятся руками.
   В пакете поля с правилом в окне не правятся — у каждой строки
   значения берутся из имени её файла (`BatchCaption`); окно даёт общие
   значения остальных полей. Блок «Правила разбора имени файла»
   с экрана «Пакет» уходит, настройка `title_parse_rules` удаляется.
7. **Поля с правилом разбора словарь не пополняют** (`record_usage`
   пропускает их сам): название ролика и состав — данные конкретного
   файла, а не словарь, из которого выбирают.
8. **Перенос данных** (миграция `c2e6f18a4d93`): каждому сообществу
   с пресетами заводится поле `Video` (жирным, без имени, без решёток,
   одно значение; занято — `Video 2`…), оно встаёт первым в каждый
   пресет с правилом «имя целиком», `{video}` в шаблоне имени файла
   становится `{Video}`. Подписи сохраняют прежний вид.

## Альтернативы

- **Одно выражение на весь пресет с именованными группами**
  (`(?P<Title>…)`). Одна строка вместо нескольких, но имя группы
  в Python обязано быть идентификатором, а имена полей бывают
  с пробелами и кириллицей; одно несовпадение обнулило бы все поля
  сразу; длинное выражение труднее писать и проверять. Отклонено.
- **Правило разбора у поля сообщества.** Проще хранить, но одно поле
  в разных пресетах разбирается по-разному — владелец прямо просил
  «произвольную разбивку в каждом пресете». Отклонено.
- **Замена вместо извлечения** (правило — только цепочка замен, как
  у прежнего названия). Замена без совпадения оставляет имя целиком,
  и поле «Starring» получило бы всё имя файла. Отклонено: нужен поиск
  с понятным «нет совпадения — нет значения».
- **Поля принадлежат пресету, без общего пула.** Убирает вопрос
  «где удалять поле», но теряется главное свойство прежней модели —
  один словарь на все пресеты (значение, введённое по одному пресету,
  видно в другом). Отклонено.
- **Правки оформления полей — сразу, без «Сохранить».** Так было в окне
  «Поля подписи…», но на одном экране два способа сохранения
  (часть сразу, часть кнопкой) сбивают с толку, а сбой второй половины
  оставлял бы первую сохранённой. Отклонено в пользу одной записи.
- **Пополнять словарь разобранными значениями** (в пакете — у отмеченных
  строк при постановке). Владелец отказался: словарь засорялся бы
  данными отдельных файлов.

## Последствия

- **Плюсы:** одно понятие «поле» вместо поля и особого названия; имя
  файла раскладывается на сколько угодно полей; настройка подписей
  живёт у сообщества; предпросмотр на образце делает регулярные
  выражения проверяемыми до отправки; уход с правок охраняется тем же
  механизмом, что у «Задач».
- **Минусы / риски:** экран пресета плотнее прежнего окна; правка
  оформления поля в одном пресете меняет его во всех (поле у сообщества
  одно — экран предупреждает об этом подсказкой). Обратный ход миграции
  структурный: поле `Video` остаётся обычным полем, `{Video}` обратно
  в `{video}` не превращается.
- **Что нужно сделать дальше:** смысловой разбор имени силами ИИ
  (этап генерации) ляжет рядом с правилами как ещё один источник
  значений поля, эти правила не отменяя.

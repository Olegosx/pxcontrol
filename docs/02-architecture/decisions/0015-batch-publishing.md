# ADR-0015. Пакетная отправка: черновики из готовой папки с раскладкой времени

> Статус: accepted
> Дата: 2026-08-15 · Автор: olegosx
>
> Опирается на [ADR-0011](0011-publish-via-userbot.md) (единый `PostDraft`),
> [ADR-0012](0012-publish-queue-in-memory.md) (очередь отправки)
> и [ADR-0014](0014-video-processing-queue.md) (пакетная обработка,
> подпапки пакетов в результатах).

## Контекст

Пакетная обработка (ADR-0014) выдаёт папку готовых видео, но отправлялись
они по одному: форма «Публикации» на каждый файл заново — канал, подпись,
время. Для регулярного наполнения канала нужно отправлять папку целиком:
разложить посты по расписанию, собрать подписи по одному шаблону
и поправить частности — не теряя возможности отправить любой файл
по-старому, поодиночке.

## Решение

1. **Пакет — это массовое создание обычных черновиков.** Никакой новой
   сущности отправки: кнопка «Пакет из папки…» на странице «Публикация»
   собирает список `PostDraft` и ставит его в существующую очередь
   отправки новым методом `PublishQueue.enqueue_many` — постановка
   атомарна (сначала проверяются все черновики, потом добавляются все).
   Дальше работают ADR-0011/0012 без изменений: маршрутизация
   по возможностям канала, отложки на сервере Telegram, карточки
   очереди, перенос в «опубликованные».
2. **Черновик пакета — правимый список.** Диалог показывает строку
   на файл: галочка («Выбрать все»/«Снять все»), подпись, переименование
   и время — каждая ячейка правится до постановки. Файл больше лимита
   канала помечается и по умолчанию снят.
3. **Раскладка времени — выбором стратегии**: «по временам канала»
   (стандартные `publish_times` вперёд по дням), «каждый день в ЧЧ:ММ»,
   «раз в N дней в ЧЧ:ММ», «каждые N часов от момента», «сейчас».
   Считает чистая функция `plan_times` (`engine/services/publish_plan.py`);
   раскладка — только начальное заполнение, время строк правится руками.
   Существующие отложки канала сознательно не опрашиваются (сеть,
   медленно, и не истина до момента отправки). Для бот-канала стратегии
   заблокированы на «сейчас» (у Bot API нет серверной отложки, ADR-0011).
4. **Подписи — общий шаблон + название из имени файла**: один проход
   существующего диалога сборки выбирает шаблон и общие значения полей;
   подпись каждой строки собирается из них с её собственным названием
   (`title_from_filename`). Заодно по шаблону имени файла каждой строке
   предлагается переименование. Всё правится построчно.
5. **Источник пакета — готовая папка**: `VideoService.scan_ready` —
   рекурсивный список видео с размером, **без ffprobe** (длительность
   отправке не нужна — скан мгновенный) и **без исключения папок
   результатов** (они и есть источник, в отличие от `scan_sources`
   из ADR-0014). Папка по умолчанию — папка результатов канала.
6. **Одиночная отправка не меняется**: пакет — дополнительный вход
   в ту же очередь, а не замена формы.

## Альтернативы

- **Своя очередь/сущность «пакет отправки».** Дублировала бы очередь
  отправки (статусы, отмена, повтор) ради группировки, которая ничего
  не решает: после постановки посты живут по одному. Отклонено.
- **Раскладка с учётом существующих отложек канала** (опрос
  `getScheduledHistory` и поиск свободных слотов). Честнее, но медленно
  (сеть на открытие диалога), требует подключённого userbot и всё равно
  не гарантирует слот к моменту отправки. Пользователь видит расписание
  на странице «Расписание» и правит времена в черновике. Отложено
  до реальной потребности (YAGNI).
- **Проход диалога подписи по каждому файлу** (как выбор кадров
  в ADR-0014). Тщательно, но для пакета в десятки файлов утомительно,
  а результат тот же достигается правкой построчно. Отклонено
  в пользу «общий шаблон + правка».

## Последствия

- **Плюсы:** папка готовых видео раскладывается по расписанию канала
  за один проход; один код отправки и одна очередь на оба сценария;
  правка любых частностей до постановки.
- **Минусы / риски:** раскладка не видит уже существующих отложек —
  совпадения слотов остаются на пользователе; таблица черновиков
  держит все строки в памяти диалога (для сотен файлов диалог станет
  тяжёлым — реальные пакеты на порядок меньше).
- **Что дальше:** очередь модерации (этап 2) сможет использовать
  ту же пару «черновики + `enqueue_many`» без интерфейсных правок.

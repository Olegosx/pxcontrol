# ADR-0027. Статистика сообщества: источники, темпы опроса, локальная история

## Контекст

Вкладке «Обзор» нужны числа и графики: участники и их динамика,
приходы и уходы, активность по часам суток, просмотры постов, итог
чистки удалённых аккаунтов. До этого решения кэш статистики держал
только текущие участники/онлайн/отложенные, а наполнялся он **показом
дашборда** — userbot-ом, раз в 15 минут, и только пока страница
открыта. Истории не было, и любой график требовал бы её накапливать.

Три обстоятельства определили выбор:

1. **У Telegram есть своя статистика** (`stats.getBroadcastStats` /
   `stats.getMegagroupStats`, MTProto): рост, подписки и отписки
   по дням, просмотры постов, активность по часам — считается сервером
   непрерывно, независимо от того, запущено ли приложение. Доступна
   администратору сообщества достаточного размера; порог — серверная
   настройка, признак `can_view_stats` приходит в `channelFull`, который
   мы и так читаем. Bot API этих методов не имеет.
2. **Дорожка аккаунта последовательна** (ADR-0024): опрос userbot-ом
   ждёт конца долгой загрузки видео, а частый опрос — это запросы
   в бюджете аккаунта, который важнее для публикации. Бот-путь дорожкой
   не регулируется (лимиты Bot API — на бота) и загрузками не задет,
   но умеет только число участников и связанный чат.
3. **Приходы и уходы из числа участников не восстановить точно**:
   по разности соседних снимков получается оценка снизу (приход и уход
   внутри интервала гасятся). Точный счёт даёт только Telegram.

## Решение

1. **Опрос — периодическая задача движка, а не показ страницы.**
   Интерфейс только читает кэш. Задача идёт тиком раз в минуту,
   проверяет, кому «пора», и выходит кооперативно (ADR-0020). Это
   первый потребитель единого планировщика опроса из ADR-0017 —
   минимальный, без частных таймеров; опрос источников на этапе 2
   встанет туда же.
2. **Два темпа по источникам.** Бот, где назначен, — **раз в 15 минут**:
   участники, связанный чат. Userbot, где есть публикатор, — **раз
   в 6 часов**, фоновым приоритетом дорожки: онлайн, отложенные, аватар,
   `can_view_stats`, связанный чат, последний пост, дата создания
   (однократно) и встроенная статистика Telegram, где доступна.
   Бот необязателен: сообщество без бота получает всё раз в 6 часов —
   осознанно, частая беготня userbot-ом задевает публикацию.
3. **Ряды — из Telegram, где есть; иначе — локальные снимки как
   оценка.** Каждый успешный проход оставляет снимок (участники, онлайн)
   в `community_stats_history`; хранение — 90 дней, старше убирает тот же
   проход. Последний ответ статистики Telegram хранится одной строкой
   на сообщество (`community_analytics`, JSON разобранных рядов) —
   историю Telegram держит сам, копить ответы незачем. Снимок «Обзора»
   называет источник рядов, интерфейс подписывает его человеку.
4. **Карточка «по часам»** показывает активность из статистики Telegram
   (просмотры у канала, сообщения у группы); онлайна по часам в ней нет —
   он берётся из снимков, только когда статистики Telegram нет.
5. **Справка** («Создана», «Привязана к», «Последний пост») добирается
   в общем проходе userbot: связанный чат — из того же `channelFull`,
   создание — первое сообщение сообщества (однократно), последний
   пост — одно чтение истории. Итог чистки удалённых аккаунтов
   (найдено, исключено, когда) записывает очередь обслуживания
   крючком — она о кэше не знает.
6. **Граница для интерфейса** — один снимок `CommunityOverviewDto`
   от сервиса статистики: числа, ряды, справка, источник. Откуда ряды
   (Telegram, снимки, в будущем — серверный сборщик) — за границей.

## Альтернативы

- **Свой бот и сервис на сервере, приложение — клиент.** Даёт
  непрерывность, но чистый бот статистику собрать не может (нет
  онлайна и методов статистики в Bot API) — сборщику всё равно нужна
  MTProto-сессия на сервере: хостинг, вторая база, секрет вне машины,
  протокол. Отложено: граница п. 6 позволяет добавить его позже.
- **TGStat.** Внешняя платная зависимость, только публичные каналы,
  без онлайна. Отклонено.
- **Только локальные снимки** (первый вариант макета). Данные лишь
  за время работы приложения, приходы/уходы — оценка. Оставлено
  запасным источником для сообществ без статистики Telegram.

## Последствия

- Число «отложено» на дашборде у сообщества без бота обновляется раз
  в 6 часов, а не при каждом показе, — плата за бережный бюджет userbot.
- Порог доступности статистики Telegram не гадается: решает
  `can_view_stats`. Живая проверка состава графиков (горизонт, имена
  рядов) — при первом прогоне на настоящем сообществе; разбор терпим
  к незнакомым именам (подсказки + позиция).
- Формат графиков Telegram разбирается чистой функцией
  (`telegram/stats_graph.py`), проверяемой на записанных ответах.
- Остановка движка гасит опрос первой из очередей: он держит дорожки
  фоновым приоритетом и не должен пережить публикацию.

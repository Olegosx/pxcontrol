# Компоненты системы

> Статус: 🟢 актуально · Обновлено: 2026-09-17 · Владелец: olegosx

## Назначение документа

Перечислить компоненты приложения, их зону ответственности и связи между
ними. Уровень детализации — крупнее, чем модули, но конкретнее, чем общий
обзор.

## Состав

### Интерфейс (PySide6 + QFluentWidgets)
- Страницы: «Пользователи и боты» (дашборд исполнителей — userbot-аккаунтов
  и ботов: сводка, разделы, карточки с состоянием, участием и действиями —
  добавить, войти, приостановить, удалить; строка активности «за 24 ч:
  N операций · занят M % · флуд-лимиты» и живая пометка дорожки,
  опрос раз в 5 с пока страница видна — [ADR-0030](decisions/0030-account-activity.md);
  правила показа — `pages/user_state.py`, [ADR-0029](decisions/0029-users-and-bots-section.md)),
  страницы аккаунтов (`pages/user_page.py` — пункты живого подменю:
  шапка с действиями, обзор активности без кнопок — плитки окон,
  графики по часам суток и по дням, виды операций, — и список
  сообществ только для чтения; действия общие с дашбордом —
  `pages/user_actions.py`; вёрстка карточек общая с «Обзором»
  сообщества — `OverviewCards` в `pages/community_overview.py`),
  «Каналы и группы» (дашборд: сводка, разделы по виду,
  плитка или список — [communities.md](../03-modules/communities.md)),
  «Видео» (пресеты и подготовка), раздел **«Публикация»** — ветка
  подменю по стадиям жизни поста ([ADR-0032](decisions/0032-publishing-section-post-stages.md),
  словарь стадий — `pages/publish_stages.py`, экраны и переходы —
  `pages/publish_section.py`): «Новый пост» (все типы контента +
  поле с оформлением текста — `pages/rich_edit.py`, ADR-0033 +
  шаблоны подписей + блок кнопок под постом, общий с правкой элемента
  очереди — `pages/markup_editor.py`, ADR-0031), «Пакет» (черновики
  из готовой папки видео — `pages/publish_batch_page.py` + редактор
  строк `pages/publish_batch.py`, ADR-0015), «Очередь» (вся очередь
  отправки приложения) и «Отложено» (записи на сервере Telegram
  с правкой, «Сейчас» и «Удалить» — ADR-0028; прежняя страница
  «Расписание» растворилась в этих двух пунктах) и «Опубликовано»
  (лента вышедших постов — `pages/published_view.py`,
  [published.md](../03-modules/published.md)); «Настройки» (категории слева: «Общие»,
  «Папки», «Ключи ИИ»).
- Адресат поста — сообщество и тема форума — общий блок обеих форм
  раздела (`pages/post_target.py`: `CommunityChoice`, `TopicChoice`).
- Опрос — свой блок обеих форм поста (`pages/poll_editor.py`):
  вопрос, варианты, анонимность, множественный выбор и викторина
  с правильным ответом ([ADR-0033](decisions/0033-rich-text-entities.md),
  C5). Сегмент «Опрос» в переключателе типа содержимого убирает поле
  текста и список файлов: у опроса их не бывает.
- Файлы поста — тоже общий блок («Новый пост» и правка элемента
  очереди): `pages/media_picker.py` показывает **список** файлов —
  один выбранный уходит обычным вложением, несколько одной записью
  (альбом, [ADR-0033](decisions/0033-rich-text-entities.md)).
  Переименование есть только у одиночного файла, и строка под списком
  честно называет, чего альбом лишён (кнопки, превью ссылки).
- Корень ветки раздела — пункт-заголовок без своей страницы; экран
  стадии (`StagePage`, `pages/stage_page.py`) работает только пока виден: скрытый не обновляет
  карточки и не ходит в Telegram. Владение очередями — вне экранов:
  наблюдатели `ui/queue_watcher.py` (по одному на очередь, реестр
  `QueueWatchers` при главном окне, [ADR-0034](decisions/0034-queue-change-notifications.md))
  подписаны на движок, держат снимок, снимают завершённые задания
  и отвечают на вопрос при закрытии окна, идёт ли работа; плашки
  об исходе и панели экранов — зрители наблюдателя.
- К движку обращается только через `EngineWorker.submit()` +
  мост `run_in_engine` (результаты возвращаются сигналами Qt; тип
  результата сквозной — mypy сверяет корутину с колбэком). Поток
  движка излучает сигналы только на бессмертном маршрутизаторе моста
  (`_Dispatcher`): излучение на одноразовых объектах гонялось с их
  `deleteLater` и падало сегфолтом в Qt (ловилось дампами ядра);
  повторяющиеся события (прогресс) идут тем же путём — `ui_callback`.
- Ошибки: пользователю показываются только читаемые тексты. Доменные
  ошибки движка (наследники `EngineError`, `engine/errors.py`) мост
  показывает как есть; любое неожиданное исключение (ошибки СУБД,
  библиотек) сворачивается в короткую «внутреннюю ошибку», полные
  детали — в лог (`user_message`). Новая доменная ошибка обязана
  наследовать `EngineError` — контракт закреплён тестом
  `test_errors.py`.
- Два вида окон ([ADR-0023](decisions/0023-work-windows-and-question-dialogs.md)):
  **короткий вопрос** — диалог-маска библиотеки (`MessageBoxBase`:
  подтверждение, ввод кода, небольшая форма) и **рабочее окно** —
  `WorkDialog` с рамками от системы (словарь, подписи, участники,
  пакеты, очередь и правка её элемента, выбор кадра): двигается,
  меняет размер, содержимое прокручивается само. Оба показываются через `exec_dialog`.
  Стили библиотечных виджетов не переопределяются — их лист
  принадлежит библиотеке (там же, п. 5).
- Общие элементы страниц — `pages/common.py`: карточки-строки, диалоги
  (показ — через `exec_dialog`, он же убирает диалог после закрытия),
  комбобокс списка DTO (`DtoComboBox` — выбор сохраняется по id,
  не по позиции). Списки карточек — два слоя (2026-09-15):
  общий **список карточек** `pages/card_list.py` (`CardList` —
  точечное обновление по снимку: меняется только изменившаяся
  карточка (`plan_cards` с произвольным ключом и отпечатком),
  а не весь список; внутри карточки заголовок и сводка меняются
  на месте, а начало шапки и кнопки пересобираются только по своим
  отпечаткам `leading_signature`/`actions_signature` (2026-09-20),
  картинки аватаров — из кэша по пути и времени изменения файла
  (`avatar_image`); крючки `editable`/`fill_body` раскрывают карточку
  формой правки, `leading` рисует начало шапки, `actions` — кнопки,
  `progress` — полосу) и надстройки над ним: **панель очереди
  движка** `pages/queue_panel.py` (`QueuePanel` — зритель наблюдателя
  очереди: снимок из его кэша, статусы каркаса заданий, действия
  «Отмена/Повторить/Убрать», прогресс; панели «Публикации», «Видео»,
  обслуживания) и панель отложенных записей Telegram (чтение
  при показе, без таймера). Правило
  показа длинного списка — `pages/list_view.py`: чистые сортировки
  и фильтры по сообществу и слоту, страницы (`paginate`), итог
  со словами списка (`summary_text`), строка управления показом
  (`ViewBar`) и перелистывание (`PagerRow`) — общие для вкладок
  «Отложено» и «Очередь» раздела «Публикация» и вкладки «Очередь»
  страницы сообщества; полоса вкладок и её пункт (`tab_strip`,
  `TabItem`) — у страницы сообщества.
  Начало шапки карточки — логотип сообщества
  и цветная метка слота времени; крючки правки передаёт только очередь
  отправки, ADR-0016), логотип сообщества (`community_logo` — аватар
  из кэша статистики, без него буква названия на подложке; общий
  для плиток дашборда и карточек очереди), метка слота
  (`slot_label`/`slot_color` — цвет выводится из времени публикации,
  один слот всегда одного цвета, разные слоты не совпадают никогда:
  час задаёт тон (24 тона по кругу, шаг разводит соседние часы
  по разным его сторонам — в очереди, отсортированной по времени,
  различать надо именно соседей), минуты — полутон того же тона;
  светлота подбирается под контраст к фону карточки, а не задаётся
  числом, иначе жёлтые метки выходили бы бледнее синих), строка
  «сейчас/дата+время» (`WhenRow`), заголовок раздела
  (`section_header` — значок, подпись, число и `HorizontalSeparator`),
  потоковая сетка карточек (`FlowGrid`/`flow_columns` — число колонок
  по своей ширине, пересборка при смене числа колонок, высота
  по содержимому; дашборд и «Обзор» сообщества),
  пары цветов текста для `setTextColor` библиотечных надписей
  (`ACCENT_TEXT`/`ERROR_TEXT`/`WARNING_TEXT`/`DIM_TEXT` — одна пара на роль, `tinted`) — ADR-0023, п. 5:
  только штатные элементы, без своих стилей и рисования; сводка очереди
  по сообществам (`QueueCounts`/`queue_counts`), присоединение панели
  очереди к наблюдателю на время показа (`QueuePanel.set_active` —
  невидимая вкладка карточки не обновляет); правила состояния сообщества и его действий —
  `pages/community_state.py` (общие для дашборда и страницы
  сообщества), красная подпись ошибки валидации
  (`ErrorLabel`), строка выбора и прокручиваемый список пакетных
  окон (`SelectionRow`, `list_area` — область без заданной
  высоты: полосу прокрутки она показывает сама).

### Движок (engine)
- UI-независимый пакет: сервисы (`accounts`, `communities`, `posts`,
  `video`, `captions`, `settings` — реестр ключей и хранение настроек
  ([ADR-0013](decisions/0013-settings-storage.md)), `publish_queue` —
  персистентная очередь отправки со слотами отложек
  ([ADR-0016](decisions/0016-persistent-publish-queue.md)),
  `video_queue` — очередь обработки видео, одиночной и пакетной
  ([ADR-0014](decisions/0014-video-processing-queue.md)),
  `maintenance` — обслуживание сообществ: чистка служебных записей
  и удалённых аккаунтов ([ADR-0026](decisions/0026-community-maintenance.md))),
  модель данных, шлюз Telegram.
- **Каркас заданий** (`engine/jobs.py`,
  [ADR-0025](decisions/0025-job-queue-framework.md)) — общий жизненный
  цикл всех трёх очередей: статусы (`JobStatus`), последовательный
  воркер, доля выполнения, отмена, повтор, отсрочка, кооперативная
  остановка. Предметные исходы («кончились слоты отложек», «файл
  исчез») переводит сам исполнитель задания; персистентность — дело
  конкретной очереди.
- Работает в фоновом потоке со своим циклом событий asyncio
  ([ADR-0006](decisions/0006-desktop-pyside6.md)) — сетевые операции
  и кодирование видео не блокируют интерфейс.
- Отложенные посты публикует сервер Telegram
  ([ADR-0010](decisions/0010-posts-fire-and-forget.md)) — своего
  планировщика в приложении нет.

### Модуль обработки видео (`engine/video/`)
- Чистый модуль поверх `ffmpeg`: файл + параметры → обработанный файл
  и кадр-превью. Не знает про Telegram, каналы и БД.
  Подробно — [video-processing.md](../03-modules/video-processing.md).

### Шлюз Telegram (`engine/telegram/`)
- Два транспорта за одним фасадом: MTProto — публикация и чтение,
  Bot API — проверки и диагностика ([ADR-0011](decisions/0011-publish-via-userbot.md)).
- Рядом с пулом транспортов — пул **дорожек**
  ([ADR-0024](decisions/0024-telegram-account-lane.md)): очередь
  обращений, зазор между запросами, приоритет операции и общая
  заморозка после флуд-лимита. Правило «лимит действует на аккаунт»
  живёт здесь одно на всё приложение. Дорожки есть и у ботов
  ([ADR-0030](decisions/0030-account-activity.md): без зазора,
  с заморозкой), и каждая дорожка записывает выполненные операции —
  учёт активности исполнителей полон по построению.
  Подробно — [telegram-gateway.md](../03-modules/telegram-gateway.md).

### Хранилище данных
- SQLite в папке приложения, миграции Alembic при старте; секреты
  шифруются, ключ — в системном хранилище ОС
  ([ADR-0009](decisions/0009-config-secrets-in-db.md)).
  Модель — [data-model.md](../05-data/data-model.md).

## Таблица ответственности

| Компонент | Отвечает за | Не отвечает за | Зависит от |
|---|---|---|---|
| Интерфейс | формы, навигация, показ прогресса/ошибок | бизнес-логику, сеть | Движок (через EngineWorker) |
| Движок (сервисы) | бизнес-логика, валидации, оркестровка | отрисовку | БД, шлюз Telegram, модуль видео |
| Модуль видео | ffmpeg-конвейер, превью | Telegram, БД | ffmpeg/ffprobe |
| Шлюз Telegram | транспорты, перевод ошибок | бизнес-правила | aiogram, Telethon |
| Хранилище | схема, миграции, шифрование секретов | файлы медиа (только пути) | SQLite, keyring |

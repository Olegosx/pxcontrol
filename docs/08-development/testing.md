# Тестирование

> Статус: 🟢 актуально · Обновлено: 2026-09-09 · Владелец: olegosx

## Назначение документа

Описать подход к тестам: что и как тестируем. Базовые правила заданы
глобально (pytest, edge cases, мок внешних вызовов) — здесь их
проекция на `pXcontrol`.

## Принципы

- Фреймворк — **pytest** (+ pytest-asyncio, `asyncio_mode = auto`).
- Тесты — плоским списком в `tests/`, по файлу на сервис/модуль
  (`test_posts.py`, `test_video_processing.py`…).
- Обязательно — граничные случаи и пути ошибок, не только «счастливый» путь.
- Внешние вызовы (Telegram, провайдер ИИ, ffmpeg) — **подменять**:
  сервисы объявляют узкие протоколы шлюза (их подменяет подставной
  объект), транспорты тестируются на подставных клиентах
  (`_FakeClient`), запуск ffmpeg подменяется monkeypatch. В реальную
  сеть тесты не ходят.
- База — настоящий SQLite во временном файле с применёнными миграциями
  (общая фикстура `db` в `tests/conftest.py`), а не мок. Там же —
  подменное хранилище ключей (`MemoryKeyring`, autouse) и общий
  подставной обработчик видео (`FakeProcessor`).
- Интерфейс (Qt) тестами не покрывается — осознанно: вся логика,
  которую стоит проверять, живёт в движке; чистые функции интерфейса
  (`parse_hhmm` и т.п.) выносятся и тестируются как обычный код.

## Что покрыто (~420 тестов)

- Сервисы: аккаунты (включая смену ключа шифрования и повторную
  активацию userbot), каналы (доступы, перепроверка в обе стороны),
  посты (маршрутизация userbot/бот, лимиты, переименование, перенос
  в «опубликованные»), видео (пресеты, подготовка, кадры-кандидаты,
  сканирование), подписи (словари, шаблоны, имена файлов).
- Очереди: отправка (ADR-0016) и обработка видео (ADR-0014) —
  постановка, пакетная `enqueue_many`, отмена, повтор, снятие с показа;
  у отправки — ещё и своё: восстановление из БД при старте, ожидание
  свободного слота отложек и выпуск из него.
- Правка элемента очереди отправки (ADR-0016, п. 7): правка поста
  с ошибкой и его возврат в работу, синхронность строки в БД, замена,
  удаление и добавление вложения (с переездом файлов между папками
  результатов и очереди), переключение «сейчас» ↔ отложенно, отказы
  (отправляющийся, смена канала, файл конвейера не как видео, пустой
  черновик, несуществующий элемент) и замок от гонки — рабочий цикл
  не забирает элемент, пока его правка сохраняется.
- Раскладка времени пакета (`schedule_plan`, ADR-0015): стратегии,
  пропуск занятых слотов.
- Транспорты: MTProto — публикация, права, отложенные, вход
  по коду/2FA, таксономия ошибок, самопочинка после старта без сети;
  Bot API — чистые помощники, перевод разметки в HTML, переводчик
  ошибок.
- Оркестрация: старт движка с недоступным userbot (нет сети,
  отозванная сессия) не роняет приложение; остановка после
  неудачного старта безопасна.
- Чистый видео-модуль: граф фильтров, геометрия кадра (ступень
  разрешения получает короткая сторона, пропорции не меняются,
  апскейл распознаётся), окно вотермарка,
  команды ffmpeg, атомарность результата (`.part` → `os.replace`),
  отмена зависшего ffmpeg (колбэк прогресса при молчании).
- Миграции: autogenerate-сравнение схемы с моделями
  (`test_schema_matches_models`), политики внешних ключей и переносы
  данных (в том числе ступень 1080 существующим пресетам).
- Чистые функции интерфейса: разбор «ЧЧ:ММ», правило показа полного
  просмотра очереди (фильтры, сортировки, нарезка на страницы, сводка),
  общие части формы поста (перечень типов вложений — с замком «у каждого
  типа есть подпись и фильтр», правила показа тем форума по роли).
- Шифрование секретов, логирование, дымовой запуск движка.

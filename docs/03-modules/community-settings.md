# Модуль «Настройки сообщества в Telegram»

> Статус: 🟢 реализовано · Обновлено: 2026-09-25 · Владелец: olegosx

## Назначение

Менять настройки канала или группы в Telegram из приложения — без
захода в официальный клиент ради каждого сообщества. Меняет публикатор
по умолчанию и в пределах своих прав. Решение —
[ADR-0043](../02-architecture/decisions/0043-community-settings-in-telegram.md).

## Что можно менять

| Раздел | Настройка | Где | Что нужно исполнителю |
|---|---|---|---|
| Основное | Фото, название (до 128), описание (до 255) | канал и группа | право «менять информацию» |
| Тип и доступ | Публичная ссылка (@имя; пусто — частное) | канал и группа | владелец |
| | Запрет копирования и пересылки | канал и группа | владелец |
| | Вступление по одобрению администратора | группа | «ограничивать участников» |
| | Писать только вступившим | группа обсуждения | «ограничивать участников» |
| Сообщения | Подписи авторов (нет · именем · со ссылкой на профиль) | канал | «менять информацию» |
| | Реакции (любые · выбранные · никаких, предел разных) | канал и группа | «менять информацию» |
| | Автоудаление (от суток до 3 месяцев) | канал и группа | «менять информацию» |
| | Автоперевод | канал, с 3-го уровня бустов | «менять информацию» |
| | Группа обсуждения | канал | «менять информацию» (только userbot) |
| Участники | Что разрешено участникам | группа | «ограничивать участников» |
| | Медленный режим (0, 10 с, 30 с, 1, 5, 15 мин, 1 ч) | группа | «ограничивать участников» |
| | Скрыть историю от новых | группа (не обсуждения, не с темами) | «менять информацию» |
| | Темы | группа (не обсуждения) | владелец |
| | Скрыть список участников | группа от 100 участников | «ограничивать участников» |
| | Усиленный антиспам | группа | «удалять сообщения» |

Права — по документации TDLib и живой пробе 25.09.2026 по одному праву
за раз; пределы и допустимые значения — там же
(`_misc/tg_settings_probe.py`, итог — `tg_settings_probe_results.txt`).
Пороги «от 100 участников» и «с 3-го уровня бустов» приложение читает
из конфигурации сервера (`help.getAppConfig`), а не держит в коде.

**Бот** (если userbot-публикатора нет или он приостановлен) меняет
только то, для чего у Bot API есть метод: фото, название, описание
и разрешения участников; стикеры, GIF, игры и встроенных ботов — только
вместе. Остальное бот читает не так, как выставлено (проба), поэтому
с его слов не показывается.

## Интерфейс

Вкладка «Настройки» страницы сообщества → строка «Настройки в Telegram —
Изменить…» → экран в той же вкладке со строкой пути «Настройки ›
В Telegram» (`ui/pages/community_tg_settings.py`):

- шапка: кто меняет (публикатор по умолчанию или бот и что ему доступно);
- разделы формы по каталогу: подпись — редактор — под ним причина,
  по которой править нельзя («Нужно право „ограничивать участников“»,
  «Только у группы обсуждения…»), или подсказка;
- одна кнопка «Сохранить» и «Отменить изменения» — активны, пока есть
  правки; уход с правками спрашивает «Сохранить / Не сохранять /
  Отмена» (общий `leave_with_question`);
- после сохранения — итог: сколько применено или перечень непринятого
  с причиной; экран показывает свежий снимок. При частичном отказе
  уход с экрана не происходит — непринятое надо увидеть;
- если править некому — объяснение и «Участники…»; если Telegram
  не ответил — причина и «Повторить».

Значение, выставленное другим клиентом и отсутствующее в перечне
(например, автоудаление на год), показывается отдельным пунктом
«задано вне приложения» и сохранением не затирается.

## Устройство

- `engine/community_settings/` — чистое ядро: **каталог** (`catalog.py`,
  одна запись на настройку: раздел, вид значения, виды сообщества,
  действие исполнителя, условие Telegram), **типы** (`model.py`:
  значения, снимок с контекстом сообщества, итог изменения)
  и **правила** (`rules.py`: доступность, проверка значения,
  изменения).
- `engine/telegram/mtproto_settings.py` — userbot: таблицы чтения
  (`READERS`) и записи (`WRITERS`) по ключам, отказы Telegram
  с текстами (`REFUSALS`), код ошибки сервера (`rpc_code` — у знакомых
  Telethon ошибок он определяется классом, в `message` там
  «BAD_REQUEST»).
- `engine/telegram/bot_settings.py` — бот: те же таблицы на четыре
  настройки.
- `engine/services/community_settings.py` — сервис: исполнитель,
  снимок, доступность, сохранение по одному изменению с итогом,
  запись названия, @имени и признака форума в сообщество.
- `ui/pages/setting_editors.py` — редакторы по видам значения
  (`EDITORS`); `ui/pages/community_tg_settings.py` — экран.

Снимок в базе не хранится: источник истины — Telegram. Справочники
сервера (конфигурация, стандартные реакции) транспорт читает один раз
за запуск.

## Как добавить настройку

1. Запись `SettingSpec` в `CATALOG` — ключ, подпись, раздел, вид,
   виды сообщества, действие; условие Telegram — функцией-преградой.
2. Чтение и запись в `READERS`/`WRITERS` userbot (и в `BOT_READERS`/
   `BOT_WRITERS`, если умеет бот); свои ошибки метода — строками
   в `REFUSALS`.
3. Тесты полноты таблиц подскажут, если что-то забыто. Экран подхватит
   настройку сам, если её вид значения уже есть; новый вид — редактор
   в `EDITORS`.

Миграций не нужно.

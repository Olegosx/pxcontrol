# Модуль «Сообщества»: каналы и группы

> Статус: 🟢 реализовано (в объёме текущих функций) · Обновлено: 2026-09-14 · Владелец: olegosx
>
> Сущность — «сообщество» (`Community`,
> [ADR-0021](../02-architecture/decisions/0021-communities-channels-and-groups.md)):
> подключённый канал или группа Telegram. Живой прогон групп, тем
> и отложек подтверждён 2026-09-06.

## Назначение

Подключение каналов и групп Telegram к приложению и учёт способов
их администрирования. Сообщество — центральная сущность: на него
ссылаются публикации, пресеты видео и шаблоны подписей. Вид (`kind`,
канал или супергруппа) определяется при подключении по сущности из API
и дальше не меняется; изменчивые свойства — признак форума (темы),
название и @имя (username; None — сообщество стало приватным) —
обновляются подключением, привязками и перепроверкой доступов.
Малые (не супер-) группы и личные чаты не подключаются — отказ
с подсказкой.

## Способы подключения (и администрирования)

Сообщество можно администрировать **ботом**, **userbot-аккаунтом**
или обоими; при подключении («Каналы и группы» → «Подключить…»)
выбирается способ. Требования к правам зависят от вида (ADR-0021):
каналу нужен админ с правом публиковать, группе — участник,
не ограниченный в отправке (боту в группе админство не требуется).

- **Через userbot** (по умолчанию): аккаунт выбирается **явно**
  из вошедших (ADR-0019) — проверяются права именно его
  (`get_permissions` через Telethon), и именно он привязывается
  к сообществу: постинг пойдёт из его сессии. Бот не нужен.
- **Через бота**: проверка через Bot API (`getChat` +
  `getChatMember`). Попутно опрашиваются вошедшие userbot-аккаунты:
  первый, кто может публиковать, привязывается (для отложек, больших
  файлов и списка тем userbot всё равно необходим, ADR-0011).

Интерфейс раздела двухуровневый. **Дашборд** «Каналы и группы»
(перестроен 2026-09-13 по макету `_misc/mockups/design_handoff_communities`):
шапка — заголовок, поиск (по названию и @имени, регистр не важен,
фильтрует на клиенте), переключатель вида «плитка / список» (положение
хранится настройкой `ui_communities_view`) и «Подключить…»; ниже —
**строка сводки**: «N в очереди отправки · M активных из K» и плашки
«N ошибок» (клик открывает окно «Вся очередь…» с фильтром «ошибки»)
и «N без публикатора» — обе только при ненулевом числе. Дальше два
раздела с заголовком (значок, подпись, число, `HorizontalSeparator`): **«Каналы»** и **«Группы»**;
пустой раздел не рисуется, фильтра «Все / Каналы / Группы» больше нет —
его работу делает само разделение.

**Плитка** — сетка с растяжением: карточка не уже 360 пикселей, число
колонок считается по ширине области, пустого поля справа нет. Карточка:
аватар из кэша (без него — буква на подложке), название, подстрочник
«@имя · 18 420 подписчиков» (у групп — «участников»; из кэша
`community_stats`, который наполняет периодический опрос движка —
ADR-0027: бот раз в 15 минут, userbot раз в 6 часов; страница кэш
только читает); строка метрик словами — «5 к отправке · 2 ждут» (очередь
приложения; «очередь пуста»), «3 отложено» (сервер Telegram; «нет
данных», пока кэш пуст) — и справа **плашка состояния** (`InfoBadge`
пресетом уровня: ошибки — красная, выключено — серая, остальное —
акцент), ровно одна по приоритету «выключено → ошибки → нет
публикатора»; выключенное сообщество приглушено штатным
`QGraphicsOpacityEffect` (макет: 0,62); числа в метриках полужирные
(`bold_numbers`). Внизу — кнопки быстрых действий (`PushButton`,
главное действие — `PrimaryPushButton`; высота 26, кегль 13 — макет),
набор по состоянию: обычное — «Опубликовать · Расписание»
(«Публикация» с предвыбранным сообществом; «Расписание» с фильтром
по нему), есть очередь — «Опубликовать · Очередь» (окно «Вся
очередь…» с фильтром по сообществу), нет публикатора — «Назначить
публикатора» (диалог «Участники…»), выключено — «Включить ·
Обслуживание», группа — «Опубликовать · Обслуживание» (без
userbot-публикатора кнопка неактивна). Правила состояния и набора
кнопок — чистые функции `card_state`/`card_actions`, закрыты тестами.

**Список** — штатная `TableWidget` на раздел по макету: строка 50,
заголовок 34, без сетки; название с аватаром 28 и @именем под ним
(виджет ячейки `_name_cell`), подписчики (у групп — участники),
к отправке («5 +2» — с ждущими слота), отложено — вправо; состояние —
та же плашка `InfoBadge`, что на карточке (`_state_cell`; штатное —
«—»); выключенная строка приглушена (0,6); колонки сортируются
кликом по заголовку, действия — контекстным меню по правому клику
(тот же набор, что кнопками). Клик по карточке или строке открывает
**страницу сообщества** — пункт живого подменю
навигации (синхронизируется с БД: подключение, удаление,
переименование).

**Страница сообщества** (перестроена 2026-09-14 по макету
`_misc/mockups/design_handoff_community_page`) — шапка и вкладки.
Шапка общая: аватар, название, плашка состояния (та же, что
на дашборде; штатное — «активен»/«активна»), подстрочник «Канал ·
@имя · N подписчиков», кнопка «Опубликовать» («Публикация»
с предвыбранным сообществом) и меню «…» (проверить доступы,
обслуживание в окне, удаление). Вкладки: **Обзор** (`ui/pages/community_overview.py`, ADR-0027) —
только справка, ни одной кнопки: справка первой (тип, создана, адрес,
ID чата, привязана к, публикатор, последний пост, обновлено с темпом
опроса), затем четыре плитки (участники и изменение
за 7 дней; онлайн у группы / просмотров на пост у канала; пришли ·
ушли за 7 дней с соотношением; удалённые аккаунты с датой прохода
обслуживания), три графика на `QPainter` (участники за 30 дней,
приходы и уходы за 14 дней от линии нуля, активность или онлайн
по часам суток с пиком) и сноска об источнике рядов — статистика Telegram или локальные
снимки (оценка); без истории вместо графиков одна строка «данных
пока нет», плитки остаются с прочерками;
**Очередь** (очередь отправки этого сообщества, ближайшие сначала:
та же панель, что на «Публикации», с правкой поста в карточке;
«Повторить ошибки» — для всех сразу, «Вся очередь…» — окно с фильтром
по сообществу; подпись карточки без названия сообщества),
**Отложено** (отложенные записи сообщества из Telegram —
`PostsService.list_scheduled(community_id)`, «Обновить»),
**Участники** (панель `MembersPanel` — та же, что в диалоге
«Участники…» с дашборда), **Обслуживание** (панель
`MaintenancePanel` — та же, что в окне; без userbot-публикатора —
объяснение и переход в «Участники»), **Настройки** (активность,
публикатор, бот, пресет и времена, «Проверить доступы» с итогом
строкой — «проверено …, userbot — …», живёт до закрытия
приложения — и за разделителем удаление, `PushButton` со значком
корзины). Вкладки — `Pivot` (подписи с полосой под активной),
прижаты влево, под всей полосой вкладок `HorizontalSeparator`;
пункт `_TabItem` держит подпись и число в своей компоновке (число
вплотную к подписи, зазор 7): у активной вкладки подпись полужирная,
число — пилюля `InfoBadge` акцентом, у остальных — приглушённая
`CaptionLabel` без подложки (макет). Карточки очереди на вкладке —
компактный режим общей панели: название обычным начертанием,
подпись под ним, полоса прогресса под названием, ошибка красит
подпись цветом ошибки, кнопки размером строки (`list_button`: 28 /
13), между шапкой и раскрытым телом разделитель. Форма правки в
раскрытой карточке — по макету: переключатель типа контента своей
ширины, поле текста 120, счётчик справа, ряд времени компактный
(`WhenRow(compact=True)`: переключатель без подписей, дата
«дд.мм.гггг» 126, время 92) с «Отмена» и «Сохранить» в том же ряду,
внизу сноска «канал получателя не меняется».
Карточка — `CardWidget`, аватар — `AvatarWidget`, таблица списка —
`TableWidget` (ADR-0023, п. 5: только штатные элементы). Тела вкладок строятся лениво при первом открытии; панели
очередей опрашивают движок только у видимой вкладки
(`QueuePanel.set_polling`); высота страницы — по видимой вкладке,
а не по самой высокой: тело вкладки — единственный виджет своей
компоновки, скрытые вкладки в ней не живут (штатный `QStackedWidget`
мерит все страницы разом и растягивал бы каждую под самую длинную). Очередь на вкладке — страницами по 20
(`QUEUE_TAB_PAGE_SIZE`, нарезка та же, что в окне «Вся очередь…»;
числа шапки и «Повторить ошибки» — по всей очереди сообщества, а не
по странице). На «Обзоре» справка о сообществе идёт первой,
числа и графики — следом. Темы форумов при публикации:
список тем читает userbot живьём, выбор — на «Публикации»
(«Общая лента» — General; закрытые темы участнику недоступны,
админу помечаются).

## Участники (ADR-0022)

В сообществе состоит пул userbot-аккаунтов (`community_members`):
публикует **аккаунт по умолчанию**, остальные — фундамент будущего
модуля соцактивности. Диалог «Участники…» на карточке: добавление
вошедшего аккаунта (права проверяются, роль — из зонда), смена
публикатора, удаление (умолчание при этом сбрасывается — без
молчаливой авто-замены). Роль («админ»/«участник») — снимок
из зондов, обновляется подключением, добавлением и перепроверкой
доступов; перепроверка обходит всех участников: подтверждённый отказ
Telegram исключает участника, сбой связи ничего не трогает.

Функциональные границы участника группы: действует медленный режим
(очередь отправки ждёт срок от сервера и повторяет сама), закрытые
темы недоступны, пост выходит от имени аккаунта — подсказка
на «Публикации» называет действующее лицо.

Действия на карточке:

- **Переключатель активности** — настройка `enabled` канала (ADR-0013):
  выключенный канал не показывается в списке выбора на «Публикации»
  и не опрашивается «Расписанием»; сам канал и его данные не трогаются.
- **«Проверить доступы»** — перепроверяет оба способа. Привязка userbot
  меняется только по подтверждённому ответу Telegram: подтверждённый
  отказ привязанного аккаунта снимает привязку; у канала без привязки
  админ ищется среди вошедших аккаунтов; сбой сети ничего не трогает.
  Потеря прав бота его не отвязывает — только предупреждение (бота
  могут вернуть). Заодно по свежим данным Telegram актуализируются
  изменчивые свойства записи: название, @имя и признак форума —
  владелец мог сменить их после подключения. Живые проверки прав
  аккаунтов попутно актуализируют и их профили (@имя, имя, фамилия
  в `tg_accounts`) — через крючок `profile_sync` движка.
- **«Участники…»** — пул userbot-аккаунтов сообщества (ADR-0022):
  добавление участника с живой проверкой его прав, смена публикатора
  по умолчанию и исключение из пула. Аккаунт при исключении остаётся
  в приложении. Отдельных действий «привязать/отвязать userbot» нет
  с этапа B ADR-0022 — привязка выражена членством и умолчанием.
- **«Настройки…»** — пресет обработки видео по умолчанию
  (`default_video_preset`: на странице «Видео» выбор этого канала
  подставляет пресет в панель) и времена публикации (`publish_times`:
  список «ЧЧ:ММ» через запятую, первое — по умолчанию; подставляются
  в строку времени на «Публикации»).
- **«Назначить бота…»** (у канала без бота) — выбор бота с проверкой
  его прав в канале; **«Отвязать бота»** — снимает связь (сам бот
  остаётся в приложении).

## Статистика ([ADR-0027](../02-architecture/decisions/0027-community-statistics.md))

Кэш статистики наполняет **периодическая задача движка**, не показ
страниц: бот, где назначен, — раз в 15 минут (участники, связанный
чат; бот-путь не зависит от загрузок userbot), userbot — раз в 6 часов
(онлайн, отложенные, аватар, справка, встроенная статистика Telegram —
где доступна по признаку `can_view_stats`). Сообщество без бота получает
всё раз в 6 часов — осознанно. Для вкладки «Обзор» сервис собирает
снимок `CommunityOverviewDto`: числа, ряды за 30/14/7 дней, профиль
по часам, справка (создано, привязано к, последний пост, обновлено)
и итог чистки удалённых аккаунтов; ряды — из статистики Telegram,
иначе из локальных снимков как оценка, и источник назван в снимке.

## Обслуживание ([ADR-0026](../02-architecture/decisions/0026-community-maintenance.md))

Уборка в сообществе — отдельный модуль: [maintenance.md](maintenance.md).
Это чистка служебных записей («такой-то вступил», «сообщение
закреплено») и удаление из списка участников мёртвых аккаунтов —
оба вида работы двумя шагами: просмотр, затем удаление
с подтверждением.
Доступно только сообществу с userbot-публикатором: списка участников
и чужой истории Bot API не отдаёт.

## Ввод ссылки

`@имя`, `t.me/…`, `t.me/c/<id>/…` или ID `-100…` (приватные каналы —
только ID). Разбор общий для обоих способов (`normalize_chat_ref`);
пригласительные ссылки `t.me/+…` отклоняются с пояснением. Понятные
ошибки: «канал не найден», «не администратор», «нет права публиковать».

## Решено

- Канал идентифицируется по `tg_chat_id` (числовой ID, уникален);
  @имя хранится справочно.
- Ботов и userbot-аккаунтов несколько; канал ссылается на своих:
  `bot_id` и `tg_account_id` (ADR-0019, миграция `e6b9d43a7f21` —
  заменила флаг `userbot_admin`).
- Мультипользовательский доступ не нужен — личный инструмент (vision).

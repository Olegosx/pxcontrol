# Модуль «Сообщества»: каналы и группы

> Статус: 🟢 реализовано (в объёме текущих функций) · Обновлено: 2026-09-21 · Владелец: olegosx
>
> Сущность — «сообщество» (`Community`,
> [ADR-0021](../02-architecture/decisions/0021-communities-channels-and-groups.md)):
> подключённый канал или группа Telegram. Живой прогон групп, тем
> и отложек подтверждён 2026-09-06.

## Назначение

Подключение каналов и групп Telegram к приложению и учёт способов
их администрирования. Сообщество — центральная сущность: на него
ссылаются публикации, пресеты видео и шаблоны подписей. Вид (`kind`,
канал или супергруппа) определяется при подключении по сущности из API
и дальше не меняется; изменчивые свойства — признак форума (темы),
название и @имя (username; None — сообщество стало приватным) —
обновляются подключением, привязками и перепроверкой доступов.
Малые (не супер-) группы и личные чаты не подключаются — отказ
с подсказкой.

## Способы подключения (и администрирования)

Сообщество можно администрировать **ботом**, **userbot-аккаунтом**
или обоими; при подключении («Каналы и группы» → «Подключить…»)
выбирается способ. Права публиковать при подключении **не требуются** (ADR-0035, п. 7):
подключение отвечает на вопрос «видно ли сообщество», а «кто и что
в нём может» — записанный снимок прав. Сообщество можно подключить
и ради чтения или реакций; если публиковать некем, состояние скажет
это прямо. Сами требования Telegram при этом никуда не делись:
в канале публикует админ с правом публиковать, в группе — участник,
не ограниченный в отправке (боту в группе админство не требуется).

- **Через userbot** (по умолчанию): аккаунт выбирается **явно**
  из вошедших (ADR-0019) — проверяются права именно его
  (`get_permissions` через Telethon), и именно он привязывается
  к сообществу: постинг пойдёт из его сессии. Бот не нужен.
- **Через бота**: проверка через Bot API (`getChat` +
  `getChatMember`). Попутно опрашиваются вошедшие userbot-аккаунты:
  первый, кто может публиковать, привязывается (для отложек, больших
  файлов и списка тем userbot всё равно необходим, ADR-0011).

Интерфейс раздела двухуровневый. **Дашборд** «Каналы и группы»
(перестроен 2026-09-13 по макету; спека —
`_misc/mockups/design_handoff/screens/communities.md`):
шапка — заголовок (в разделе из навигации — с надстрочником «Каналы
и группы»), поиск (по названию и @имени, регистр не важен, фильтрует
на клиенте), переключатель вида «плитка / список» и «Подключить…».
Вид хранится настройкой `ui_communities_view`, и по умолчанию она
`auto`: раздел до 12 сообществ показывается плиткой, больше — списком
(`effective_view`); нажал переключатель — дальше действует выбор
человека. Ниже — **строка сводки**: «N в очереди отправки · M активных
из K», затем «N ошибки в очереди» (клик ведёт на «Публикация» →
«Очередь» с фильтром «ошибки») и «N не могут публиковать» — оба
сегмента только при ненулевом числе, у обоих число в плашке
(`InfoBadge` уровнем: ошибки красные, проблемы публикации —
предупреждение), а текст — ссылкой. Второй сегмент включает
**клиентский фильтр**: остаются те, кому публиковать некем
(`matches_problem` — публикатор не назначен, приостановлен или лишён
прав), под сводкой появляется строка «Показаны только те, кто не может
публиковать» со ссылкой «Показать все»; фильтр и поиск действуют
вместе. Дальше два
раздела с заголовком (значок, подпись, число, `HorizontalSeparator`): **«Каналы»** и **«Группы»**;
пустой раздел не рисуется, фильтра «Все / Каналы / Группы» больше нет —
его работу делает само разделение.

**Плитка** — сетка с растяжением: карточка не уже 360 пикселей, число
колонок считается по ширине области, пустого поля справа нет. Карточка:
аватар из кэша (без него — буква на подложке), название, подстрочник
«@имя · 18 420 подписчиков» (у групп — «участников»; из кэша
`community_stats`, который наполняет периодический опрос движка —
ADR-0027: бот раз в 15 минут, userbot раз в 6 часов; страница кэш
только читает); строка метрик словами — «5 к отправке · 2 ждут» (очередь
приложения; «очередь пуста»), «3 отложено» (сервер Telegram; «нет
данных», пока кэш пуст) — и справа **плашка состояния** (`InfoBadge`
пресетом уровня: ошибки — красная, всё, что мешает публиковать, —
предупреждение, выключено — серая; акцент остаётся штатному «активен»
в шапке страницы), ровно одна по приоритету «выключено → ошибки → публикатор
приостановлен → публикатор без прав → нет публикатора»
(«публикатор приостановлен» —
назначенный есть, но на паузе, ADR-0029: карточка предлагает
«Возобновить «имя»» — ту же операцию, что кнопка на странице
исполнителя; при активном втором публикаторе состояние штатное); выключенное сообщество приглушено штатным
`QGraphicsOpacityEffect` (макет: 0,62); числа в метриках полужирные
(`bold_numbers`). Внизу — кнопки быстрых действий (все `PushButton`,
высота 26, кегль 13 — макет; акцентных среди них нет: главное действие
страницы — «Подключить…»). Правило набора: **у каждой проблемы своя
первая кнопка**, а тому, кто публиковать не может, «Опубликовать»
не предлагается вовсе. Обычное — «Опубликовать · Отложено» («Новый
пост» с предвыбранным сообществом; «Отложено» с фильтром по нему),
есть очередь — «Опубликовать · Очередь», ошибки — «Ошибки в очереди ·
Опубликовать» (очередь этого сообщества с фильтром «ошибки»),
нет публикатора или он без прав — «Назначить публикатора» (диалог
«Участники…»), публикатор на паузе — «Возобновить «имя»», выключено —
«Включить», группа — «Опубликовать · Задачи» (без userbot-публикатора
кнопка неактивна). Правила состояния и набора
кнопок — чистые функции `card_state`/`card_actions`, закрыты тестами.

**Список** — штатная `TableWidget` на раздел по макету: строка 50,
заголовок 34, без сетки, заголовок без вертикальных разделителей
(официальная добавка `setCustomStyleSheet`, ADR-0023 п. 5); название с аватаром 28 и @именем под ним
(виджет ячейки `_name_cell`), подписчики (у групп — участники),
к отправке («5 +2» — с ждущими слота), отложено — вправо; состояние —
та же плашка `InfoBadge`, что на карточке, но текстом покороче
(«приостановлен», «без прав»; полный — подсказкой, `_state_cell`;
штатное — «—»); выключенная строка приглушена (0,6); колонки сортируются
кликом по заголовку, действия — контекстным меню по правому клику
(тот же набор, что кнопками). Клик по карточке или строке открывает
**страницу сообщества** — единственную на всё приложение
([ADR-0041](../02-architecture/decisions/0041-navigation-fixed-tree.md)):
в навигации сообществ нет, вход к ним — только отсюда. Пункты-группы
«Каналы» и «Группы» в навигации показывают тот же дашборд, суженный
до раздела: свой заголовок с надстрочником, своя подсказка поиска,
своя сводка, заголовков разделов нет.

**Страница сообщества** (перестроена 2026-09-14 по макету; спека —
`_misc/mockups/design_handoff/screens/community-page.md`) — шапка и вкладки.
Шапка общая: аватар, название, плашка состояния (та же, что
на дашборде; штатное — «активен»/«активна»), подстрочник «Канал ·
@имя · N подписчиков», кнопка «Опубликовать» («Публикация»
с предвыбранным сообществом) и меню «…» (проверить доступы,
обслуживание в окне, удаление). Вкладки: **Обзор** (`ui/pages/community_overview.py`, ADR-0027) —
ни одной кнопки и ни одного переключателя, только смотрят. Порядок
сверху вниз (спека, раздел 4): **главный ряд** — четыре числа жёсткой
сеткой 1 × 4, всегда в одну строку (у канала: подписчики и изменение
за 7 дней, пришли · ушли, просмотров на пост долей подписчиков,
уведомления включены; у группы: участники, пришли · ушли, онлайн
сейчас, удалённые аккаунты с датой прохода обслуживания; нет данных —
«—» и «нет данных», плитка не исчезает). Дальше **разделы
по вопросам** (`overview_sections` — чистая функция с тестом: раздел
без данных не рисуется вместе с заголовком): «Аудитория» (участники
за 30 дней, приходы и уходы за 14 от линии нуля, откуда новые, языки,
звук уведомлений), «Посты» у канала (плитки пересылок и реакций
на пост и на истории; просмотры и пересылки, Instant View, истории,
откуда просмотры, реакции — и таблица недавних постов), «Сообщения»
у группы (плитки сообщений, читающих и пишущих; сообщения по дням,
читающие и пишущие), «Когда читают» (часы суток и дни недели),
«Люди» у группы (таблицы самых активных, администраторов
и пригласивших). Внутри раздела: плитки потоковой сеткой (`FlowGrid`
из `common`, минимум 180), под ними карточки такой же сеткой
(минимум 340: три в ряд при окне 1160, две при 820), а таблицы —
**во всю ширину после сетки** (иначе соседняя карточка стояла
с пустым низом: высота строки сетки равна самой высокой). Графики —
`QPainter` (единственное разрешённое исключение), ряды по дням —
сгруппированными столбцами (`_GroupedBars`, легенда точками
`DotInfoBadge`, имена рядов по-русски через `series_title`), доли —
строками «имя — `ProgressBar` — %» (больше восьми — «прочее»,
`share_rows`). В конце — раздел «О сообществе» (тип, создана, адрес,
ID чата, привязана к, публикатор, последний пост, обновлено с темпом
опроса) и сноска об источнике рядов: статистика Telegram или локальные
снимки (оценка). Ни одного раздела с данными — строка «данных пока
нет», главный ряд остаётся с прочерками;
**Очередь** (очередь отправки этого сообщества, ближайшие сначала:
та же панель, что на «Публикации», с правкой поста в карточке;

**Участники** (панель `MembersPanel` — та же, что в диалоге

пула — «Пользователи» и «Боты» — сеткой карточек; число на вкладке —

**Задачи** (панель

только у видимой вкладки (`QueuePanel.set_active`); высота страницы — по видимой вкладке,
а не по самой высокой: тело вкладки — единственный виджет своей
компоновки, скрытые вкладки в ней не живут (штатный `QStackedWidget`
мерит все страницы разом и растягивал бы каждую под самую длинную). Очередь на вкладке — страницами по 20
(`QUEUE_TAB_PAGE_SIZE`, нарезка и перелистывание те же, что на экране «Очередь» — `list_view.paginate`/`PagerRow`;
числа шапки и «Повторить ошибки» — по всей очереди сообщества, а не
по странице). На «Обзоре» первыми идут главные числа, а справка
о сообществе — последним разделом: её читают один раз, числа —
каждый раз. Темы форумов при публикации:
список тем читает userbot живьём, выбор — на «Публикации»
(«Общая лента» — General; закрытые темы участнику недоступны,
админу помечаются).

## Исполнители (ADR-0022, ADR-0035)

В сообществе работает **пул исполнителей обоих видов**
(`community_executors`): userbot-аккаунты и боты — строка на каждого,
с участием и полным снимком прав. Ботов, как и людей, может быть
несколько, и админство ни от кого не требуется: исполнитель нужен
и ради чтения, реакций, обслуживания.

**Членство — факт, а не пропуск.** Строка живёт, пока её не убрал
человек; потеря прав и выход из сообщества меняют участие, но членство
и назначение не трогают. Прежде подтверждённый отказ Telegram исключал
участника, и вместе с ним пропадала настройка: вернули права — публикатора
назначай заново.

**Назначения хранятся отдельно от прав**, по одному на вид:
`default_tg_account_id` (публикатор-пользователь) и `default_bot_id`
(публикатор-бот, он же рисует кнопки под постом). Права приходят
от Telegram, назначение принимает человек, и смешивать их нельзя:
назначить можно и того, кто сейчас публиковать не может, — состояние
сообщества скажет об этом честно («публикатор без прав»).

**Публикует пул, умолчание — предпочтение**
([ADR-0036](../02-architecture/decisions/0036-executor-dispatch-and-urgency.md),
2026-09-21). Способные публиковать пользователи пула
(`publishing_users` в `community_rights.py`: не на паузе, по снимку прав
могут) — кандидаты на каждый пост; кого из них поручить, решает
диспетчер (`services/dispatch.py`): свободный раньше занятого загрузкой,
меньше ожидающих — раньше, при равенстве — публикатор по умолчанию.
Требования поста отсекают неподходящих до ранжирования: файл больше
2000 МиБ или подпись длиннее 1024 знаков повезёт только аккаунт
с Premium. Поэтому «есть ли чем публиковать» (`community_capabilities`)
отвечает по пулу, а не по одному назначенному, и сообщество публикует
даже без назначенного умолчания. Причины «некому» тоже считаются
по пулу: «приостановлен» — когда способных нет, но среди
приостановленных есть способный по правам; «без прав» — когда
не приостановленные в пуле есть, а права публиковать ни у кого нет.
**Лицо публикации** (этап D, 2026-09-21). В группе по умолчанию пост
уходит **от имени группы**: его несёт администратор с правом
«анонимность» (действие `PUBLISH_AS_COMMUNITY`), и транспорт называет
`send_as` явно. Иное лицо человек выбирает в ряду «От имени» формы —
тогда пост уходит именно им или ждёт его. Бот пишет от своего имени,
поэтому в группе он несёт лицо «сообщество» только у поста с кнопками —
и форма говорит об этом заранее. В канале выбора нет: пост всегда
от имени канала.

То же правило — для всех операций сообщества (этап C, 2026-09-21):
бот-путь и кнопки берут бота из пула по правам (`PUBLISH`,
`EDIT_OTHERS`), чтения (темы, лента, отложки канала), статистика,
обслуживание и ввод исполнителя спрашивают состоящего исполнителя
в порядке диспетчера. Одна точка ответа «кому поручить» —
`ranked_executors` в `community_rights.py`; назначения (`default_*`)
остаются предпочтением при равной занятости.

Вкладка (и диалог «Участники…» с дашборда) показывает сверху **блок
«Публикатор по умолчанию»** — по карточке на вид (`SimpleCardWidget`):
роль, назначенный (аватар, имя, роль) и список смены `DtoComboBox`
шириной 150 с пунктом-заглушкой «Сменить…». В списке — исполнители
этого вида, которые могут публиковать и не приостановлены
(`default_candidates`); выбор — существующая операция
`set_default_publisher`. Публикатора нет — «не назначен».

Ниже — пул двумя разделами, «Пользователи» и «Боты», сеткой карточек
(`FlowGrid`, минимум 340). Ввод нового исполнителя переехал в заголовок
раздела (`DtoComboBox` 220 и «Ввести» той же высоты), ошибка ввода —
строкой под своим заголовком. Карточка исполнителя — постоянной высоты
62: аватар 32 (у приостановленного приглушён), имя с одной плашкой
(`member_badge`: «по умолчанию» акцентом, «приостановлен» серым,
«не может публиковать» предупреждением), под ним роль (у бота —
«@имя · роль») и три кнопки-значка: «Возобновить» (только
у приостановленного, та же операция, что в разделе «Пользователи
и боты»), «Права» и «Убрать». Текстовых кнопок в ряду нет: они съедали
колонку имени.

В окне «Участники…» с дашборда панель лежит в прокрутке (во вкладке её
прокручивает страница). Интервалы: между блоками — интервал блока,
внутри блока (заголовок, пояснение, сетка) — интервал строки.

**Права — всплывающей панелью** (`Flyout` с `FlyoutViewBase`, ширина
420) по кнопке-значку: что выдано администратору, что можно как
участнику и когда права прочитаны. Карточка больше не раскрывается —
раскрытие тянуло высоту всего ряда сетки, а перечень нужен изредка.
Пустая отметка чтения честно говорит, что права перенесены из прежней
модели и ждут перепроверки.

Перечисляется **только выданное**: список из трёх десятков строк, где
половина «нельзя», человек читать не станет, а отсутствие права и значит
«не выдано». Администратору разрешения участника не перечисляются вовсе —
вместо них сказано, что ограничения на него не действуют: это правило
Telegram, а не наше послабление.

Правила показа исполнителя (подпись, плашка, кандидаты в публикаторы,
перечень прав, тексты исходов ввода и подтверждений) — чистый модуль
`ui/pages/executor_text.py`, он же
держит словарь прав по-русски: снимок хранит телеграмные имена
(`post_messages`, `send_reactions`), а человеку нужны слова.

Число на вкладке — `executors_count`, весь пул. Настройки сообщества
строк про публикаторов не содержат — кто публикует, решается одним местом.

### Ввод исполнителя в сообщество

Исполнителя, которого в сообществе ещё нет, приложение **вводит само** —
лестницей от простого к сложному, и усложнение только по названной
причине:

1. **уже состоит** — в Telegram не ходим вовсе, только читаем и
   записываем права;
2. **публичное сообщество** — аккаунт вступает сам по @имени: ступень
   не зависит ни от чьих прав и ни от чьих настроек приватности;
3. **приватное** — вступаем по ссылке-приглашению, которую приложение
   **читает** у Telegram (она у сообщества уже есть и приходит тем же
   ответом, что и статистика). Читает её администратор пула с правом
   приглашать — участнику с тем же правом Telegram ссылку не показывает,
   поэтому спрашиваются все такие администраторы по очереди, а не
   первый, кто может приглашать. Своих ссылок приложение не создаёт:
   создание — изменение состояния сообщества, за которым тянется
   вопрос «кто её завёл и кто по ней пришёл»;
4. **приглашение силами пула** — если ссылки Telegram не отдал,
   исполнителя приглашает наш же администратор с правом приглашать;
5. **вопрос человеку** — ссылку вставляют руками. Ступень последняя
   потому, что единственная останавливает операцию: звать человека,
   пока остаются автоматические пути, значит звать зря.

Приглашение с одобрением даёт исход **«заявка отправлена»**: строка
исполнителя заводится со статусом «заявка отправлена», но участником
он ещё не считается — прав нет, публиковать нельзя, и приложение
говорит это прямо.

**Бот сам вступить не может** — у Bot API такого метода нет. В группу
его приглашает исполнитель из пула, в канал принимает назначением
администратором: участником бот в канале не бывает. Права при
назначении называются заранее и ровно те, ради которых бот нужен, —
публиковать и править сообщения (кнопки под постом, ADR-0031).
Некому ввести — честный отказ с объяснением, что сделать руками:
у приложения нет прав, которых нет у его исполнителей.

Вступление и приглашение делаются **только по явному действию
человека** — по нажатию «Ввести», по одному исполнителю за раз,
с приоритетом «человек ждёт ответа». В фоне приложение в чужие
сообщества не вступает никогда: массовое вступление — самый верный
способ получить ограничение аккаунта.

Лестница живёт отдельно от хранения — класс `ExecutorJoiner` в чистом
модуле `engine/services/executor_join.py`: ему дают строки сообщества
и исполнителя, он ходит в Telegram через шлюз и возвращает исход
со свежим снимком прав, а отказ поднимает ошибкой `JoinError`
с объяснением, что сделать руками. Сервис сообществ (`communities.py`)
только оркестрирует: находит строки, зовёт лестницу и записывает
результат. Правила над уже записанным пулом — кто публикатор, готов ли
он, приостановлен ли, что умеет сообщество — тоже вынесены в чистый
модуль `community_rights.py`, и посты с кнопками читают их оттуда же,
не через сервис.

Участие («владелец», «админ», «участник», «ограничен», «не состоит»,
«исключён», «заявка отправлена») и **полный перечень прав** — снимок
из зондов (ADR-0035):
обновляется подключением, добавлением исполнителя и перепроверкой
доступов. Перепроверка обходит весь пул своим транспортом на каждого. Три исхода
зонда различаются строго: подтверждённый ответ обновляет снимок;
подтверждённое «его здесь нет» (выгнали, вышел, закрыли; у бота — 403)
записывает участие «не состоит», оставляя назначение на месте; сбой
связи ничего не трогает. Отправленная заявка перепроверку переживает:
для Telegram заявитель — «не участник», но след нашего действия
стирать нельзя — статус сменится, когда заявку одобрят. Умолчание
сбрасывается только тогда, когда человек убрал исполнителя из пула, —
без молчаливой авто-замены.

Функциональные границы участника группы: действует медленный режим
(очередь отправки ждёт срок от сервера и повторяет сама), закрытые
темы недоступны, пост выходит от имени аккаунта — подсказка
на «Публикации» называет действующее лицо.

Действия **на карточке дашборда** — только быстрые, по состоянию
сообщества (`card_actions`): выключенному — «Включить», без публикатора —
«Назначить публикатора», у группы — «Опубликовать» и «Задачи»,
у канала с непустой очередью — «Опубликовать» и «Очередь», иначе
«Опубликовать» и «Отложено». У сообщества с приостановленным
публикатором действий нет вовсе: возобновляют его в разделе
«Пользователи и боты», а звать назначать нового вместо возврата
прежнего — плохой совет.

**Дашборд обновляется по отпечатку** (2026-09-20, аудит быстродействия):
раздел «Каналы» или «Группы» появляется с первым сообществом и исчезает
с последним, карточка живёт, пока не сменился её отпечаток
(`row_signature`: снимок сообщества, сводка очереди, подписчики, число
отложенных, путь аватара), изменившаяся заменяется новой целиком
(общие `GridSection`/`SectionStack` в `pages/dashboard.py`, те же
у дашборда исполнителей); таблица вида «список» пересобирается только
при смене отпечатка строк или сортировки; сводка над разделами меняет
числа на месте. Снимок очереди отправки дашборд и шапка страницы
сообщества не запрашивают — они постоянные зрители наблюдателя
главного окна (ADR-0034), и числа очереди на карточках живые. При показе
читаются только список сообществ и кэш статистики.

Всё остальное переехало на **страницу сообщества** (13–14.09.2026):
переключатель активности, «Проверить доступы», настройки и бот — во
вкладку «Настройки» и меню «…», участники и обслуживание — в свои
вкладки. Ниже — что эти действия делают, независимо от того, откуда
их вызвали:

- **Переключатель активности** — настройка `enabled` канала (ADR-0013):
  выключенный канал не показывается в списке выбора на «Публикации»
  и не опрашивается экраном «Отложено»; сам канал и его данные не трогаются.
- **«Проверить доступы»** — перепроверяет оба способа. Привязка userbot
  меняется только по подтверждённому ответу Telegram: подтверждённый
  отказ привязанного аккаунта снимает привязку; у канала без привязки
  админ ищется среди вошедших аккаунтов; сбой сети ничего не трогает.
  Потеря прав бота его не отвязывает — только предупреждение (бота
  могут вернуть). Заодно по свежим данным Telegram актуализируются
  изменчивые свойства записи: название, @имя и признак форума —
  владелец мог сменить их после подключения. Живые проверки прав
  аккаунтов попутно актуализируют и их профили (@имя, имя, фамилия
  в `tg_accounts`) — через крючок `profile_sync` движка.
- **«Участники…»** — пул исполнителей сообщества обоих видов
  (ADR-0035): ввод исполнителя (вступление, ссылка, приглашение —
  см. лестницу выше), смена публикатора по умолчанию своего вида
  и удаление из пула. Исполнитель при удалении остаётся и в приложении,
  и в самом Telegram — уходит только работа приложения через него.
  Отдельных действий «привязать/отвязать userbot» нет с этапа B
  ADR-0022 — привязка выражена членством и умолчанием.
- **«Настройки…»** — пресет обработки видео по умолчанию
  (`default_video_preset`: на странице «Видео» выбор этого канала
  подставляет пресет в панель) и времена публикации (`publish_times`:
  список «ЧЧ:ММ» через запятую, первое — по умолчанию; подставляются
  в строку времени на «Публикации»).
- **Ввод и удаление бота** — в разделе «Боты» вкладки «Участники»:
  ботов там может быть несколько, публикатор-бот один. «Ввести» просит
  Telegram принять бота (в группу приглашением, в канал назначением
  администратором), «Убрать» удаляет его из пула с подтверждением —
  и предупреждает, что вместе с публикатором-ботом пропадают кнопки
  под постами и запасной путь публикации.

## Статистика ([ADR-0027](../02-architecture/decisions/0027-community-statistics.md))

Кэш статистики наполняет **периодическая задача движка**, не показ
страниц: бот, где назначен, — раз в 15 минут (участники, связанный
чат; бот-путь не зависит от загрузок userbot), userbot — раз в 6 часов
(онлайн, отложенные, аватар, справка, встроенная статистика Telegram —
где доступна по признаку `can_view_stats`). Сообщество без бота получает
всё раз в 6 часов — осознанно. Для вкладки «Обзор» сервис собирает
снимок `CommunityOverviewDto`: числа, ряды за 30/14/7 дней, профиль
по часам, справка (создано, привязано к, последний пост, обновлено)
и итог чистки удалённых аккаунтов; ряды — из статистики Telegram,
иначе из локальных снимков как оценка, и источник назван в снимке.

## Задачи ([ADR-0038](../02-architecture/decisions/0038-community-tasks.md))

Работа в сообществе по поручению человека — отдельный модуль:
[tasks.md](tasks.md). Сегодня это чистка служебных записей
(«такой-то вступил», «сообщение закреплено») и удаление из списка
участников мёртвых аккаунтов (правила — ADR-0026) — оба вида двумя
шагами: просмотр, затем удаление с подтверждением; у каждой задачи
свой журнал запусков. Доступно только сообществу с userbot-публикатором:
списка участников и чужой истории Bot API не отдаёт.

## Ввод ссылки

`@имя`, `t.me/…`, `t.me/c/<id>/…` или ID `-100…` (приватные каналы —
только ID). Разбор общий для обоих способов (`normalize_chat_ref`);
пригласительные ссылки `t.me/+…` отклоняются с пояснением. Понятные
ошибки: «бот не видит это сообщество» (по числовому ID Telegram
отвечает только участнику — добавить бота или указать публичное
`@имя`), «бот не добавлен», «сообщество закрыто от аккаунта»; тексты
нейтральны к сценарию, потому что та же проверка служит и вводу бота
в уже подключённое сообщество, где ID взят из базы. Нехватка прав
ошибкой не считается — она попадает в снимок (ADR-0035, п. 7).

## Решено

- Канал идентифицируется по `tg_chat_id` (числовой ID, уникален);
  @имя хранится справочно.
- Ботов и userbot-аккаунтов несколько; сообщество ссылается на своих
  публикаторов по умолчанию: `default_tg_account_id` и `default_bot_id`
  (ADR-0019, миграция `e6b9d43a7f21` заменила флаг `userbot_admin`;
  ADR-0022 выразила участие таблицей `community_members`; ADR-0035
  заменила её пулом `community_executors` обоих видов со снимком прав,
  миграция `b5c1e83d7a64`, — а колонки хранят тех из пула, кто публикует).
- Мультипользовательский доступ не нужен — личный инструмент (vision).

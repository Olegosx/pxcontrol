# Модуль «Сообщества»: каналы и группы

> Статус: 🟢 реализовано (в объёме текущих функций) · Обновлено: 2026-09-06 · Владелец: olegosx
>
> Сущность — «сообщество» (`Community`,
> [ADR-0021](../02-architecture/decisions/0021-communities-channels-and-groups.md)):
> подключённый канал или группа Telegram. Живой прогон групп, тем
> и отложек подтверждён 2026-09-06.

## Назначение

Подключение каналов и групп Telegram к приложению и учёт способов
их администрирования. Сообщество — центральная сущность: на него
ссылаются публикации, пресеты видео и шаблоны подписей. Вид (`kind`,
канал или супергруппа) определяется при подключении по сущности из API
и дальше не меняется; признак форума (темы) — изменчивый флаг,
обновляется подключением, привязками и перепроверкой доступов.
Малые (не супер-) группы и личные чаты не подключаются — отказ
с подсказкой.

## Способы подключения (и администрирования)

Сообщество можно администрировать **ботом**, **userbot-аккаунтом**
или обоими; при подключении («Каналы и группы» → «Подключить…»)
выбирается способ. Требования к правам зависят от вида (ADR-0021):
каналу нужен админ с правом публиковать, группе — участник,
не ограниченный в отправке (боту в группе админство не требуется).

- **Через userbot** (по умолчанию): аккаунт выбирается **явно**
  из вошедших (ADR-0019) — проверяются права именно его
  (`get_permissions` через Telethon), и именно он привязывается
  к сообществу: постинг пойдёт из его сессии. Бот не нужен.
- **Через бота**: проверка через Bot API (`getChat` +
  `getChatMember`). Попутно опрашиваются вошедшие userbot-аккаунты:
  первый, кто может публиковать, привязывается (для отложек, больших
  файлов и списка тем userbot всё равно необходим, ADR-0011).

Карточка показывает вид («Канал» / «Группа» / «Группа-форум»),
публикаторов с ролью умолчания и число прочих участников; список
фильтруется по виду в шапке страницы. Темы форумов при публикации:
список тем читает userbot живьём, выбор — на «Публикации»
(«Общая лента» — General; закрытые темы участнику недоступны,
админу помечаются).

## Участники (ADR-0022)

В сообществе состоит пул userbot-аккаунтов (`community_members`):
публикует **аккаунт по умолчанию**, остальные — фундамент будущего
модуля соцактивности. Диалог «Участники…» на карточке: добавление
вошедшего аккаунта (права проверяются, роль — из зонда), смена
публикатора, удаление (умолчание при этом сбрасывается — без
молчаливой авто-замены). Роль («админ»/«участник») — снимок
из зондов, обновляется подключением, добавлением и перепроверкой
доступов; перепроверка обходит всех участников: подтверждённый отказ
Telegram исключает участника, сбой связи ничего не трогает.

Функциональные границы участника группы: действует медленный режим
(очередь отправки ждёт срок от сервера и повторяет сама), закрытые
темы недоступны, пост выходит от имени аккаунта — подсказка
на «Публикации» называет действующее лицо.

Действия на карточке:

- **Переключатель активности** — настройка `enabled` канала (ADR-0013):
  выключенный канал не показывается в списке выбора на «Публикации»
  и не опрашивается «Расписанием»; сам канал и его данные не трогаются.
- **«Проверить доступы»** — перепроверяет оба способа. Привязка userbot
  меняется только по подтверждённому ответу Telegram: подтверждённый
  отказ привязанного аккаунта снимает привязку; у канала без привязки
  админ ищется среди вошедших аккаунтов; сбой сети ничего не трогает.
  Потеря прав бота его не отвязывает — только предупреждение (бота
  могут вернуть).
- **«Привязать userbot…»** (у канала без привязки) — выбор аккаунта
  с проверкой его прав; **«Отвязать userbot»** — снимает привязку
  (аккаунт остаётся в приложении).
- **«Настройки…»** — пресет обработки видео по умолчанию
  (`default_video_preset`: на странице «Видео» выбор этого канала
  подставляет пресет в панель) и времена публикации (`publish_times`:
  список «ЧЧ:ММ» через запятую, первое — по умолчанию; подставляются
  в строку времени на «Публикации»).
- **«Назначить бота…»** (у канала без бота) — выбор бота с проверкой
  его прав в канале; **«Отвязать бота»** — снимает связь (сам бот
  остаётся в приложении).

## Ввод ссылки

`@имя`, `t.me/…`, `t.me/c/<id>/…` или ID `-100…` (приватные каналы —
только ID). Разбор общий для обоих способов (`normalize_chat_ref`);
пригласительные ссылки `t.me/+…` отклоняются с пояснением. Понятные
ошибки: «канал не найден», «не администратор», «нет права публиковать».

## Решено

- Канал идентифицируется по `tg_chat_id` (числовой ID, уникален);
  @имя хранится справочно.
- Ботов и userbot-аккаунтов несколько; канал ссылается на своих:
  `bot_id` и `tg_account_id` (ADR-0019, миграция `e6b9d43a7f21` —
  заменила флаг `userbot_admin`).
- Мультипользовательский доступ не нужен — личный инструмент (vision).

# Модуль «Подписи к постам»

> Статус: 🟢 реализовано · Обновлено: 2026-09-25 · Владелец: olegosx

## Назначение

Быстрая сборка подписей из полей со словарями и из разбора имени файла:
подпись к видео за несколько кликов, а в пакете — без кликов на каждый
файл. Решение — [ADR-0042](../02-architecture/decisions/0042-caption-presets.md).

## Модель

- **Поле сообщества** (`caption_fields`) — имя («Genre», «Year»,
  «Video»…) и **оформление** (`FieldStyle`): решётки или текст,
  одно или несколько значений, имя в подписи (`show_name`: выключено —
  в строку уходят только значения), **жирным** (`bold`). Название
  ролика — обычное поле с оформлением «жирным, без имени, без решёток».
  У поля — **словарь значений** (`caption_values`), общий для всех
  пресетов сообщества: значение, добавленное при сборке по одному
  пресету, сразу видно в остальных.
- **Связь полей** (`parent_field_id`) — поле может жить внутри другого:
  «Character» внутри «Title». Тогда у значения словаря есть родитель
  (`parent_value_id`): персонаж принадлежит своему тайтлу.
- **Пресет подписи** (`caption_presets` + `caption_preset_fields`) —
  именованный упорядоченный набор полей сообщества и необязательный
  шаблон имени файла. У каждой строки состава — необязательное
  **правило разбора имени файла** (`source_rule`, JSON; NULL — значение
  вводит человек). Пресетов у сообщества сколько угодно; в окне сборки
  предвыбирается последний использованный (`last_used_at`).
  До ADR-0042 пресеты назывались «шаблонами подписи».

## Разбор имени файла в значения полей

Правило (`SourceRule`) применяется к имени файла **без расширения
и без суффикса конвейера** `_<пресет>_<штамп>` (`filename_source`;
суффикс — технический след обработки видео, связка с форматом штампа
закреплена тестом). Шаги:

1. **Извлечение** — поиск регулярным выражением. Значение — группа
   с именем `value`, иначе первая группа, иначе всё совпадение. Пустое
   выражение — имя целиком. **Нет совпадения — у поля нет значения**:
   поле, заполненное всем именем файла, хуже пустого.
2. **Очистка** — цепочка замен «что найти → на что заменить»; каждый
   шаг работает по результату предыдущего. Пустая замена — удаление,
   пробел — обычное значение (им разбивают слипшиеся слова:
   `[_-]` → пробел). В замене допустимы ссылки на группы (`\1`,
   `\g<имя>`).
3. **Разделение** — только у поля с несколькими значениями: по
   выражению-разделителю (по умолчанию запятая).
4. **Регистр** каждого значения («Как есть», «Каждое Слово С Заглавной» —
   без порчи «iPhone», «Только первая буква»), схлопывание пробелов,
   отсев пустых значений и повторов.

Пример из постановки задачи. Имя `11.12.2014 627563 Bruce Lee, Jan Clod
Van Dam, Ded Morozz (Prosto Film)`:

| Поле | Извлечение | Результат |
|---|---|---|
| Title (жирным, без имени) | `\(([^()]*)\)\s*$` | **Prosto Film** |
| Starring (несколько, решётки) | `^\S+\s+\d+\s+(.+?)\s*\(` | Starring: #BruceLee, #JanClodVanDam, #DedMorozz |

Битая часть правила при разборе пропускается со следом в журнале —
разбор сотни имён не падает из-за опечатки. Сохранить битое правило
нельзя: проверка одна (`check_rule`) — экран показывает причину рядом
с полями, движок отказывает при сохранении.

Заготовки выражений — единая точка в движке: `EXTRACT_PRESETS`
(текст в последних скобках, текст до первой скобки, первая дата, год)
и `STEP_PRESETS` для очистки (скобки с содержимым, даты, слова из одних
цифр, номера по краям, перечень слов, метки качества и релиза).
У заготовки даты группа `value` обязательна: внутри неё есть свои группы
разделителей, и «первая группа» вернула бы разделитель.

**Заготовка дат** покрывает ходовые написания: `2024-01-31`,
`31.01.2024`, `31.01.24`, `24-01-31`, слитное `20240131`. Разделитель
внутри одной даты одинаковый (`31.01-24` датой не считается), по краям
запрещена цифра. **Одиночный год датой не считается**: «Blade Runner
2049» переживает разбор.

## Сборка подписи

- `build_caption(lines)` — строки полей по порядку пресета; строки без
  значений пропускаются; строка с оформлением «жирным» выделяется
  **сущностью разметки** (ADR-0033), смещение — в кодовых единицах
  UTF-16. Telethon применяет сущности сам; на запасном бот-пути
  транспорт переводит разметку в HTML
  (см. [telegram-gateway.md](telegram-gateway.md)).
- `CaptionPresetDto.parsed(source)` — значения полей с правилом;
  `CaptionPresetDto.lines(values, enabled)` — строки подписи.
- `hashtag` («Tomb Raider» → `#TombRaider`).

## Словари

- `record_usage` пополняет словари значениями из сборки (без дублей
  по регистру) и отмечает пресет использованным. **Поля с правилом
  разбора словарь не пополняют**: название ролика и состав — данные
  конкретного файла.
- `add_values` / `delete_value` — ручная правка словаря из окна
  «Словарь…».
- Связанные словари: `update_field(field_id, FieldEdit(style, parent))`
  объявляет поле зависимым (смена связи обнуляет привязки значений —
  они указывали в прежний словарь; правка одного оформления привязки
  не трогает), `assign_value_parent` привязывает значение руками,
  `add_values(..., parent_value_id)`, `FieldDto.available(parent_ids)` —
  значения, подходящие выбранному родителю.

### Связанные словари: персонаж внутри тайтла

- **При сборке поста** список значений зависимого поля показывает только
  значения выбранного родителя; смена тайтла перестраивает список сразу.
- **Значения без привязки видны всегда** — иначе их нельзя было бы
  ни выбрать, ни привязать.
- **Новые значения привязываются сами**: персонаж, введённый руками
  при выбранном тайтле, после отправки попадает в словарь уже внутри
  него (`record_usage` обрабатывает поля от родителей к зависимым).
  Привязка выполняется, когда у родителя выбрано ровно одно значение.
- **Тёзки — разные записи**: «Lara» в «TombRider» и «Lara» в другом
  тайтле живут отдельно (дубли считаются в пределах родителя).
- **Значение без родителя усыновляется** при первом использовании
  вместе с тайтлом.
- **Удаление тайтла удаляет его персонажей** (каскад в схеме, решение
  от 15.08.2026) — окно словаря предупреждает об этом.
- **Удаление всего родительского поля** словарь зависимого не трогает:
  значения отвязываются, поле становится независимым с целым словарём
  (аудит 2026-08-15).

## Интерфейс

- **Вкладка «Настройки» страницы сообщества**, блок «Пресеты подписи»:
  строки пресетов (состав, поля из имени файла, задан ли шаблон имени)
  и «Создать пресет». Клик по строке открывает **экран пресета** в той
  же вкладке — строка пути «Настройки › пресет» (`caption_presets.py`).
- **Экран пресета**: имя; **образец имени файла** («Из файла…» берёт
  имя настоящего файла; образец не сохраняется) — по нему под каждым
  полем виден результат разбора, а внизу — итоговая подпись и имя
  файла; поля пресета карточками — оформление (галочки), «внутри: …»,
  порядок стрелками, «Словарь…», меню «…» («Убрать из пресета»,
  «Удалить поле из сообщества…» с перечнем пресетов, из которых оно
  уйдёт, и размером словаря); у поля — «Брать из имени файла»
  и редактор правила (`caption_rule.py`: извлечение с заготовками,
  цепочка очистки, регистр, разделитель); «Добавить поле» — поле
  сообщества вне пресета или «Новое поле…»; шаблон имени файла
  с подсказкой плейсхолдеров.
- **Сохранение одно на весь экран** — одной записью движка
  (`save_preset`: имя, состав, правила, шаблон имени и правки
  оформления и связей полей). Кнопки «Сохранить» и «Отменить изменения»
  неактивны, пока экран совпадает с сохранённым. Сразу выполняются
  только операции над пулом полей: заведение нового поля и удаление
  поля из сообщества (с подтверждением). Уход с правками — путь
  «Настройки», другая вкладка, другое сообщество — спрашивает
  «Сохранить / Не сохранять / Отмена» (общий признак
  `UnsavedChanges`, как у «Задач»).
- Оформление и связь поля **общие для всех пресетов** сообщества:
  поле у сообщества одно.
- **Окно «Словарь…»** — рабочее окно (ADR-0023): значения пилюлями
  в поточной раскладке с крестиком удаления, добавление пачкой через
  запятую; у зависимого поля значения сгруппированы по родителю
  (в конце — «Без привязки»), перенос в другую группу — правый щелчок.
- **«Публикация» → «Собрать подпись…»** — окно сборки: выбор пресета,
  поля со словарями; поля с правилом заранее заполнены из имени
  первого файла поста (значение из словаря отмечено пилюлей, новое
  вписано строкой); ненужные поля отключаются галочками. Результат
  вставляется в поле подписи и правится руками. Если пресетов нет,
  подсказка отправляет в «Настройки» сообщества.

## Переименование файла при отправке

У пресета есть необязательный **шаблон имени файла**
(`filename_pattern`), например `{Author}, {Video} ({Genre}) {quality}
(@{channel})`. Плейсхолдеры: `{ИмяПоля}` — значения поля через запятую
(без решёток); встроенные (`FILENAME_PLACEHOLDERS`) — `{quality}`
(меньшая сторона кадра видео, ffprobe) и `{channel}` (@имя канала);
встроенные главнее полей-тёзок; неизвестные остаются как есть.

После сборки подписи движок вычисляет имя (`render_filename`; чистая
часть — `compose_filename`: подстановка, очистка недопустимых
символов, расширение исходника), на странице появляется строка
«Переименовать при отправке» — имя правится руками, галочка отключает.
Предел длины имени — **в байтах UTF-8** (`MAX_FILENAME_BYTES` = 240,
с учётом расширения): лимит файловых систем байтовый, кириллица
занимает два байта на букву; обрезка не рвёт символ посередине. Поверх
действует лимит Telegram (`TELEGRAM_MAX_STEM_CHARS` = 78 символов
стема — длиннее сервер молча режет и чистит, см.
[правила](telegram-filenames.md)): стем режется так, чтобы имя
заканчивалось **законченным словом**; сплошное слово без разделителей
режется как есть. При отправке `PostsService` переименовывает файл
**и его кадр-превью** на диске (`PostDraft.rename_to`), занятое имя
или путь в имени — понятная ошибка до отправки.

## Пакетная публикация

Окно сборки проходится один раз на пакет (ADR-0015): поля с правилом
в нём помечены «из имени каждого файла» и не правятся, остальные дают
общие значения. Подпись и предлагаемое имя каждой строки собираются
из общих значений и значений, разобранных из имени её файла
(`BatchCaption`, `publish_batch.py`). До ADR-0042 на экране «Пакет»
жил блок «Правила разбора имени файла» с настройкой сообщества
`title_parse_rules` — разбор переехал в правила полей пресета,
настройка удалена миграцией.

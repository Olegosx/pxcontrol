# Модуль «Подписи к постам»

> Статус: 🟢 реализовано · Обновлено: 2026-08-15 · Владелец: olegosx

## Назначение

Быстрая сборка подписей вида «жирное название + строки "Поле: #значения"»
на странице «Публикация». Цель — подпись к видео за несколько кликов.

## Модель

- **Поле канала** (`caption_fields`) — имя («Genre», «Year»…), оформление
  значений (решётки/текст), множественность. У поля — **словарь значений**
  (`caption_values`), общий для всех шаблонов канала: значение, добавленное
  при сборке по одному шаблону, сразу видно в остальных.
- **Связь полей** (`parent_field_id`) — поле может жить внутри другого:
  «Character» внутри «Title». Тогда у значения словаря есть родитель
  (`parent_value_id`): персонаж принадлежит своему тайтлу.
- **Шаблон** (`caption_templates` + `caption_template_fields`) — именованный
  упорядоченный набор полей канала. Шаблонов у канала сколько угодно;
  в диалоге предвыбирается последний использованный (`last_used_at`).

## Поведение

- `CaptionsService` — CRUD полей/шаблонов, `record_usage` (автопополнение
  словарей использованными значениями, без дублей по регистру),
  `add_values`/`delete_value` — ручная правка словаря из редактора.
- Чистые функции: `build_caption` (название `**жирным**` — Markdown,
  Telethon применяет его по умолчанию; пустые поля пропускаются),
  `hashtag` («Tomb Raider» → `#TombRaider`), `title_from_filename`
  (имя файла без суффикса конвейера `_<пресет>_<штамп>`).
- Связанные словари: `set_field_parent` (объявить поле зависимым; смена
  связи обнуляет привязки значений — они указывали в прежний словарь),
  `assign_value_parent` (привязать значение руками),
  `add_values(..., parent_value_id)`, `FieldDto.available(parent_ids)` —
  значения, подходящие выбранному родителю.
- Интерфейс: на «Публикации» — «Собрать подпись…» (диалог: шаблон,
  название из имени файла, поля со словарями; ненужные поля отключаются
  галочками) и «Поля подписи…» (настройка пула полей и шаблонов;
  порядок полей шаблона — перетаскиванием; у каждого поля — кнопка
  «Словарь…»: редактор словаря с удалением значений и добавлением
  новых через запятую). Результат вставляется в поле подписи
  и правится руками.

## Связанные словари: персонаж внутри тайтла

Поле объявляется зависимым от другого поля канала — в диалоге «Поля
подписи…» у поля есть выбор «внутри: …». После этого:

- **при сборке поста** список значений зависимого поля показывает только
  значения выбранного родителя: выбрали тайтл — видите его персонажей.
  Смена тайтла перестраивает список сразу, без переоткрытия диалога;
- **значения без привязки видны всегда** — иначе их нельзя было бы
  ни выбрать, ни привязать;
- **новые значения привязываются сами**: персонаж, введённый руками
  при выбранном тайтле, после отправки попадает в словарь уже внутри
  него (`record_usage` обрабатывает поля от родителей к зависимым).
  Привязка выполняется, когда у родителя выбрано ровно одно значение;
- **тёзки — разные записи**: «Lara» в «TombRider» и «Lara» в другом
  тайтле живут отдельно (дубли считаются в пределах родителя);
- **значение без родителя усыновляется** при первом использовании
  вместе с тайтлом — словарь связывается по мере работы;
- **удаление тайтла удаляет его персонажей** (каскад в схеме, решение
  от 15.08.2026) — редактор словаря предупреждает об этом.

Связи правятся руками в редакторе «Словарь…»: у каждого значения —
выбор родителя, у строки добавления — тайтл для новых значений.

## Переименование файла при отправке

У шаблона подписи есть необязательный **шаблон имени файла**
(`filename_pattern`), например `{Author}, {video} ({Genre}) {quality}
(@{channel})`. Плейсхолдеры: `{video}` — название видео (нарочно
не `{title}`: у каналов бывает поле «Title», различие только регистром
путало; миграция `b6d4f82e9c13`); `{ИмяПоля}` — значения
поля через запятую (без решёток); `{quality}` — меньшая сторона кадра
видео (ffprobe); `{channel}` — @имя канала; неизвестные остаются как есть.

После сборки подписи движок вычисляет имя (`render_filename`: подстановка,
очистка недопустимых символов, расширение исходника), на странице
появляется строка «Переименовать при отправке» — имя правится руками,
галочка отключает. Предел длины имени — **в байтах UTF-8**
(`MAX_FILENAME_BYTES` = 240, с учётом расширения): лимит файловых
систем байтовый (ext4 — 255 байт), кириллица занимает два байта
на букву; обрезка не рвёт символ посередине. Поверх действует лимит
Telegram (`TELEGRAM_MAX_STEM_CHARS` = 78 символов стема — длиннее
сервер молча режет и чистит, см. [правила](telegram-filenames.md)):
стем режется так, чтобы имя заканчивалось **законченным словом** —
срез в середине слова откатывается к концу предыдущего, висячие знаки
препинания убираются; сплошное слово без разделителей режется как есть. При отправке `PostsService` переименовывает файл
**и его кадр-превью** на диске (`PostDraft.rename_to`), занятое имя
или путь в имени — понятная ошибка до отправки.

# Модуль «Подготовка видео»

> Статус: 🟢 реализовано (подготовка) · Обновлено: 2026-08-15 · Владелец: olegosx

## Назначение

Готовит видеофайл к публикации в Телеграме: FullHD-вписывание, вотермарк,
заставка для красивого превью, обложка. Порт наработок из референса
`makeVideo` (поведение — по его `SPEC.md`).

## Архитектурная граница (важно)

**Подготовка отделена от публикации.** Контракт — путь к файлу:

- `engine/video/` — **чистый модуль**: файл + `ProcessingOptions` →
  обработанный файл. Не знает про Telegram, каналы и БД. Синхронный
  (как и его тесты); async-граница — в сервисе (`asyncio.to_thread`).
- `services/video.py` — `VideoService`: пресеты в БД (`video_presets`),
  маппинг пресета в `ProcessingOptions`, пути и человеческие ошибки.
  Папки видео — из настроек приложения («Настройки → Папки», ключи
  `video_source_dir` / `video_processed_dir` / `video_published_dir`;
  пусто — `media/source|processed|published` в папке приложения);
  внутри каждой — **подпапка пресета** (`subdir`, поле в карточке
  «Вывод»; при создании пресета заполняется его именем). Диалоги выбора
  файлов открываются в соответствующих папках.
- Публикация готового файла — зона `PostsService.publish` (единая
  сущность `PostDraft`, ADR-0011): кнопка «Опубликовать…» на карточке
  результата открывает страницу «Публикация» с предзаполненными файлом
  и каналом (выбранным на «Видео»). После успешной публикации видео
  (и его кадр-превью) переезжает из папки результатов в папку
  опубликованных с сохранением подпапки («зеркалим относительный
  путь»); файл не из папки результатов остаётся на месте.
- Результат собирается во временном имени `<результат>.mp4.part`
  в той же папке (формат задан явно: `-f mp4`) и переезжает в конечное
  имя атомарно и только при успехе — упавшее кодирование не оставляет
  обрезков в «Готовых видео» (аудит 2026-08-15). Имя пресета в имени
  файла чистится от спецсимволов ОС, подчёркивания меняются на дефисы —
  суффикс `_<пресет>_<штамп>` остаётся разборчивым для названия поста.
- Конвейер сохраняет кадр-превью рядом с результатом (`<имя>.png`:
  кадр заставки/обложки, иначе первый кадр). При публикации из него
  режется JPEG-миниатюра ≤320×320 с сохранением пропорций (квадрат
  нельзя — Telegram растягивает миниатюру до пропорций видео); для
  чужого видео без превью — случайный кадр из середины. Метаданные
  для Telegram извлекает `hachoir` (иначе миниатюра игнорируется).

## Состав чистого модуля

| Файл | Что делает |
|---|---|
| `probe.py` | метаданные через ffprobe (размеры, длительность, fps, звук, битрейт) |
| `filtergraph.py` | сборка `-filter_complex`: FullHD, вотермарк с окном показа, заставка hold+xfade — чистые функции |
| `frames.py` | кадр заставки: random-middle / first / time / frame / image |
| `pipeline.py` | сборка и запуск команды ffmpeg, вшивание обложки (`attached_pic`) |
| `ffmpeg.py` | единый запуск ffmpeg/ffprobe: лог команды, перевод ошибок, прогресс |

## Пресеты и панель параметров

Параметры обработки живут **прямо на странице «Видео»** (панель
`_PresetForm`): «Обработать» применяет то, что на экране, ничего
не сохраняя — `VideoService.prepare` принимает готовые поля
(`PresetFields`) и в БД за пресетом не ходит. Пресет (таблица
`video_presets`) — «загрузчик»: выбор в списке заполняет панель,
«Сохранить» перезаписывает выбранный пресет состоянием панели,
«Сохранить как…» создаёт новый, «Удалить» — удаляет. Пресет
необязателен: панель с настройками по умолчанию работает сразу.

Обрезка с краёв: `trim_start`/`trim_end` — сколько секунд отрезать
в начале и в конце (0 — не резать; доли секунды допустимы). Срез —
входными аргументами ffmpeg (`-ss`/`-t`), точный (идёт перекодирование).
**Все остальные параметры считаются от обрезанной версии**: окно показа
вотермарка, момент кадра заставки (`time:5` — 5-я секунда обрезанного),
случайные кадры и кандидаты — только из обрезанного диапазона.
Обрезка больше длительности ролика — понятная ошибка до кодирования.

Затухание на краях: `fade_in`/`fade_out` — длительность появления
из чёрного в начале и ухода в чёрное в конце (сек; 0 — без эффекта).
В форме — карточка «Затухание» под «Обрезкой»: края включаются
чекбоксами, длительность — в полях рядом (по умолчанию 2 с; поле
активно при включённом чекбоксе; выключенный край хранится нулём).
Эффект самостоятельный (к обрезке не привязан, хотя отлично маскирует
срез), накладывается на итоговые видео **и звук** (`fade`/`afade`);
при заставке звуковое появление стартует вместе со звуком (после
тишины задержки). Затухания, не помещающиеся в итог, — понятная
ошибка до кодирования.

Качество видео: поле `video_bitrate_kbps` — целевой битрейт; NULL
(по умолчанию) — «как в оригинале»: берётся битрейт исходника из ffprobe,
а если тот его не сообщил — постоянное качество CRF 20.

Рекомендация битрейта (`VideoService.bitrate_advice`): если выбранный
исходник больше лимита Telegram на файл (2000 МиБ; 4000 — у аккаунта
с Premium, см. [шлюз](telegram-gateway.md)), движок считает битрейт
видео, дающий итог «лимит минус 1 %» (запас на контейнер): бюджет ×
0,99 × 8 / длительность после обрезки, минус фиксированные 192 кбит/с
аудио. На странице «Видео» значение подставляется в «Качество, Мбит/с»
автоматически — поверх «0 — как в оригинале» или прежней автоподстановки
(рекомендация нового файла обновляет рекомендацию старого, а выбор файла
в лимите сбрасывает её в «0» — от предыдущего файла ничего не остаётся,
2026-08-15). Заполненное вручную или пресетом поле не трогается; ручной
«0» снова освобождает поле для автоподстановки. Слишком длинное видео,
которое не влезает в лимит даже с минимальным качеством, — понятная
ошибка.

Комментарий в метаданные (`meta_comment`): свободный текст — обычно
«ссылка на канал — описание» — пишется тегом `comment` контейнера MP4
при кодировании (пусто — не пишется; вшивание обложки тег сохраняет).
Telegram метаданные не индексирует — это брендинг файла за пределами
поста: свойства файла, плееры, парсеры площадок при перезаливе.

Вотермарк масштабируется под кадр с сохранением пропорций: `scale`
со вторым входом-эталоном (`rw`, высота `-2`). Устаревший `scale2ref`
не используется — в ffmpeg 8 он искажает размер и пропорции.

Цвета вотермарка: RGB→YUV — явно матрицей bt709 (по умолчанию ffmpeg
берёт bt601, и оттенки сдвигались), смешивание overlay — в `yuv444`
(по умолчанию yuv420: цветность в четверть разрешения, тонкие штрихи
перенимали цвет соседей). Остаточное ограничение — сам формат H.264
yuv420p: у штрихов в 1–2 пикселя цветность частично теряется при любом
кодировании; лекарство — крупнее масштаб вотермарка или жирнее шрифт.

Флаг поворота в метаданных (вертикальное видео, записанное альбомным
кадром, — норма для телефонов) учитывается при чтении метаданных
(`probe_video` меняет ширину и высоту местами): ffmpeg сам поворачивает
кадры при декодировании, и расчёты идут от реальной ориентации —
раньше такое «книжное» видео кодировалось растянутым альбомным
(исправлено 2026-08-15).

Размер итогового кадра считается в Python (`fitted_size`, вписывание
в FullHD с чётными сторонами): основное видео и кадр заставки приводятся
к одному явному размеру — фильтр склейки `xfade` требует точного
совпадения размеров входов. Своя картинка-заставка с иными пропорциями
вписывается с чёрными полями по центру (letterbox), а не валит обработку.
Пресет по умолчанию для канала реализован настройкой канала
`default_video_preset` (ADR-0013, см. [channels.md](channels.md)
и [configuration.md](../06-config/configuration.md)) — колонки в таблице
каналов под это нет.

## Выбор кадра заставки

Режимы источника кадра: случайный из середины, **случайные кадры
на выбор**, момент времени, своя картинка. В режиме «на выбор» при
запуске обработки открывается плитка из N случайных кадров (по умолчанию
6, диапазон 5–95 % длительности; «Обновить» — новая партия). Кандидаты
извлекаются сразу в финальном качестве (PNG в размере итогового кадра),
выбранный файл уходит в обработку как есть (`image:<путь>`) — без
повторного извлечения и риска соседнего кадра. Партией кандидатов
владеет `VideoService`: предыдущая удаляется при каждом новом запросе.
Кадры выбираются **до постановки в очередь** (для пакета — диалог
по разу на файл, с именем файла в заголовке): выбранный PNG копируется
в папку очереди (`ProcessingQueue.stash_frame`), потому что следующая
партия кандидатов стёрла бы его; отмена выбора для пакета — предложение
исключить файл, не трогая остальные. Без человека (будущая автоматика)
режим откатывается к случайному кадру из 5–95 %.

## Очередь обработки и пакетный режим (ADR-0014)

Вся обработка — и одиночная, и пакетная — идёт через **очередь
в памяти движка** (`ProcessingQueue`, `engine/services/video_queue.py`;
устройство — по образцу очереди отправки постов, ADR-0012): элементы
кодируются строго по одному (x264 сам загружает все ядра), ошибка
одного файла не трогает остальные, у элемента с ошибкой есть
«Повторить». Отмена кодирующегося элемента кооперативная: колбэк
прогресса бросает служебное исключение, и `run_streaming` убивает
процесс ffmpeg. Очередь не переживает перезапуск (о непустой очереди
предупреждает подтверждение выхода); готовые результаты при этом
остаются на диске — запись атомарна.

Пакет: кнопка «Обработать папку…» → выбор папки (по умолчанию —
действующая папка исходников) → диалог сканирования
(`VideoService.scan_sources`: рекурсивный обход в отдельном потоке,
длительность каждого файла через ffprobe, ход виден). Папки результатов
и опубликованных исключаются из обхода; скрытые файлы/папки
и недописанные `.part` пропускаются. В списке (имя с относительным
путём, размер, длительность) файлы отмечаются галочками («Выбрать
все»/«Снять все»); нечитаемые ffprobe по умолчанию сняты. Результаты
пакета кладутся в **подпапку пакета**
`<результаты>/<подпапка пресета>/<штамп>_<имя папки-источника>/`.
Исходник больше лимита Telegram получает **рекомендуемый битрейт
автоматически** (пакет спросить не может; заданный вручную битрейт
ниже рекомендации не повышается) — пометка видна в карточке элемента.

## Интерфейс

Страница «Видео»: строка источника — **файл или папка в одном месте**
(путь к исходнику с «Обзор…» и кнопкой просмотра системным плеером,
рядом — «Обработать папку…» как альтернативный источник-пакет) →
строка пресета (список-загрузчик + кнопки сохранения/удаления) →
панель параметров (поля заставки активны только при включённом
переключателе) → «Обработать» → **панель очереди обработки**
(итоговая строка «готово M из N» и карточка на элемент: статус,
полоса прогресса с процентами — ffmpeg отчитывается через
`-progress pipe:1`, — отмена/повтор/снятие с показа, у готового —
«Опубликовать…») → раздел **«Готовые видео»**. Кодирование — в фоновом
потоке, окно и форма живы; новые готовые элементы сами обновляют список.

Раздел показывает **всю подпапку папки результатов**, а не только
последний результат: карточка на файл (имя, размер, дата изменения;
новые — сверху) с кнопками «Открыть», «Показать в папке»,
«Опубликовать…» и удалением. Обход рекурсивный: результаты пакетов
лежат во вложенных подпапках и показываются с относительным именем
(«пакет/файл.mp4»). Подпапка берётся из панели параметров —
та же, куда уйдёт следующий результат, поэтому список перечитывается
при её правке, при загрузке пресета, при открытии страницы и после
обработки. Удаление (`VideoService.delete_processed`) спрашивает
подтверждение и уносит вместе с видео его кадр-превью; путь вне папки
результатов сервис отклоняет — промах интерфейса не должен стереть
чужой файл. Список отдаёт `VideoService.list_processed(subdir)`
(чтение каталога — в отдельном потоке): в нём только видеофайлы
(`VIDEO_SUFFIXES`), несуществующая подпапка — пустой список.

Окно показа вотермарка задаётся **отступами от краёв ролика**
(`wm_start_offset` — появление через N секунд от начала,
`wm_end_offset` — скрыть за N секунд **до конца**; 0/пусто — без
ограничения): отступы переносимы между роликами разной длины,
в абсолютное окно они превращаются конвейером по длительности из
ffprobe. Отступы, не помещающиеся в ролик, — понятная ошибка
до кодирования.

Плавность появления/исчезания (`wm_fade`, сек; 0 — резко): `fade`
по альфа-каналу на краю окна с ненулевым отступом. Статичной картинке
эффект по времени недоступен (кадр один), поэтому при плавности она
зацикливается фильтром `loop` в поток, обязательно ограниченный
`trim` по длительности итога — бесконечный вторичный вход `overlay`
не даёт ffmpeg завершиться. Переходы, не помещающиеся в окно, —
ошибка до кодирования.

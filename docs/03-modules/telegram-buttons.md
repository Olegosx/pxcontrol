# Кнопки под постом: что Telegram позволяет (документация и опыт)

> Статус: 🟢 готов (часть правил — вычислена опытным путём) · Обновлено: 2026-09-15 · Владелец: olegosx

## Назначение документа

Собрать в одном месте, что можно и чего нельзя делать с **кнопками
под постом канала** (инлайн-клавиатурой): что прямо сказано в официальной
документации, а что выяснено живым опытом. На этих правилах стоит
[ADR-0031](../02-architecture/decisions/0031-buttons-post-then-markup.md).

Документ нужен потому, что в этой области ходит много неверных общих
утверждений («бот правит только свои сообщения»), и одно из них оказалось
ложным именно в нашем случае — канал, где бот администратор.

## Что такое кнопки в терминах Telegram

Кнопки — отдельное поле сообщения (`reply_markup`), а не часть текста.
Видов два:

- **Инлайн-клавиатура** (`replyInlineMarkup`) — кнопки под самим
  сообщением. Единственный вид, применимый к посту канала.
- **Обычная клавиатура** (`replyKeyboardMarkup`) — заменяет экранную
  клавиатуру собеседника в диалоге с ботом; к каналу неприменима.

## Из официальной документации

| Правило | Источник |
|---|---|
| Кнопки ставит только бот: поле описано как «Reply markup for sending **bot** buttons» | [messages.sendMessage](https://core.telegram.org/method/messages.sendMessage) |
| То же в библиотеках: «This parameter will only work if you have signed in as a bot» (Telethon), «For bots only» (Pyrogram) | [Telethon](https://docs.telethon.dev/), [Pyrogram](https://docs.pyrogram.org/api/methods/send_message) |
| Бот не может создать отложенную запись: `SCHEDULE_BOT_NOT_ALLOWED` — «Bots cannot schedule messages» | [messages.sendMedia](https://core.telegram.org/method/messages.sendMedia) |
| В Bot API поля времени публикации нет вовсе | [sendMessage](https://core.telegram.org/bots/api#sendmessage) |
| Бот заливает файл до 50 МБ, скачивает до 20 МБ | [Bots FAQ](https://core.telegram.org/bots/faq) |
| Отправка по `file_id` не требует перезаливки; идентификатор годен только тому боту, который его получил | [Bot API: Sending files](https://core.telegram.org/bots/api#sending-files) |
| Виды инлайн-кнопок: `url`, `copy_text`, `callback_data`, `web_app` (только личка), `login_url`, `switch_inline_query*`, `pay` | [InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton) |
| События бота (`getUpdates`) хранятся 24 часа и достаются одному читателю | [getUpdates](https://core.telegram.org/bots/api#getupdates) |
| У отправки альбома (`sendMediaGroup`) параметра `reply_markup` **нет вовсе** | [sendMediaGroup](https://core.telegram.org/bots/api#sendmediagroup) |
| Право «изменять сообщения» (`can_edit_messages`) — «can edit messages of other users and can pin messages; **for channels only**»: в группах бот чужие сообщения править не может | [ChatMemberAdministrator](https://core.telegram.org/bots/api#chatmemberadministrator) |
| Копия сообщения (`copyMessage`) принимает **свою** клавиатуру и не связана с исходным сообщением | [copyMessage](https://core.telegram.org/bots/api#copymessage) |

## Проверено опытом 15.09.2026

Условия: два приватных тестовых канала; userbot-аккаунт — администратор
обоих; бот — администратор обоих с правами «публиковать» и **«изменять
сообщения»**; клавиатура проб — кнопка-ссылка и кнопка «скопировать
текст». Скрипт и сырые выводы — `_misc/tg_buttons_probe.py` и
`_misc/tg_buttons_probe_results.txt` (папка вне git).

| Что проверялось | Результат |
|---|---|
| **Бот добавляет кнопки к посту, опубликованному userbot-ом** | **Получается.** `editMessageReplyMarkup` на чужой пост прошёл — у бота есть право «изменять сообщения» в канале |
| То же для поста **с вложением** (видео) | Получается — главный случай приложения |
| То же для элемента **альбома** | **Не получается:** Telegram отвечает «ничего не изменилось», то есть разметку у сгруппированного сообщения отбрасывает |
| **Бот копирует пост со склада своими кнопками** (`copyMessage`) | Получается: копия чистая (плашки «переслано» нет), кнопки на месте, видео 59,8 МБ ушло без перезаливки — копирование серверное, лимит 50 МБ не применяется |
| Отложка userbot-а → публикация сервером → бот дорисовывает кнопки | Получается целиком: пост вышел сам, бот нашёл его в событиях `channel_post`, правка добавила клавиатуру |
| Пометка «изменено» после такой правки | Не появляется: у сообщения `edit_hide=True`; подтверждено глазами владельца в клиенте |
| Бот правит **отложенный** пост (до выхода), в т.ч. по MTProto | Отказ: `BotMethodInvalidError` (метод недоступен ботам) и `ScheduleBotNotAllowedError` |
| Обычная пересылка поста с кнопками | Кнопки сохраняются, но остаётся плашка «переслано из…» |
| Пересылка без автора (`drop_author`) | **Кнопки исчезают** — и при немедленной, и при отложенной |
| Отложенная пересылка с автором | Кнопки сохраняются (и в отложенных, и после публикации), плашка «переслано» остаётся |
| Файл 59,8 МБ, отправленный ботом по `file_id` | Уходит с кнопками: лимит 50 МБ действует только на заливку |
| userbot правит текст поста бота (в канале) | Кнопки сохраняются |
| Бот правит свой пост, не передав клавиатуру заново | **Кнопки стираются** |
| Замена вложения у вышедшего поста публикателем | Работает, **кнопки сохраняются**; тип вложения менять можно (видео → фото) — кнопки тоже живы |
| Замена вложения у отложенной записи | Работает (в ответе сервера новое вложение и текст) |
| **Группа:** бот дорисовывает кнопки к сообщению пользователя | **Отказ:** «Bad Request: message can't be edited»; у бота-администратора группы поля `can_edit_messages` нет вовсе |
| **Группа:** бот отправляет своё сообщение с кнопками | Работает |
| **Группа:** пользователь правит сообщение бота | **Отказ:** `MessageAuthorRequiredError` — в группе каждый правит только своё |
| Бот меняет вложение своего поста | Работает; **без повторной передачи клавиатуры кнопки исчезают**, с передачей — сохраняются |
| Бот правит текст, передав клавиатуру заново | Кнопки сохраняются |
| Бот снимает кнопки (пустая разметка) | Снимаются |
| Публикатор пробует снять кнопки | **Не может:** текст меняется, клавиатура остаётся |
| Опрос с кнопками от бота, правка его кнопок | Работает и то, и другое |
| Правка подписи альбома публикателем | Работает (кнопок у альбома нет и быть не может) |

## Пределы клавиатуры (вычислены опытом)

В документации их нет, и при превышении сервер **не жалуется** — молча
теряет кнопки. Проверять обязано приложение.

| Предел | Значение | При превышении |
|---|---|---|
| Кнопок в одном ряду | **8** | лишние молча отбрасываются |
| Рядов в клавиатуре | **100** | лишние молча отбрасываются |
| Длина подписи кнопки | **128 символов** | молча обрезается |
| Копируемый текст кнопки «скопировать» | 1–256 символов (по документации) | явный отказ `BUTTON_COPY_TEXT_INVALID` |

## Правила, которые из этого следуют

1. **Кнопки и авторство разделимы.** Пост может опубликовать userbot
   (любой размер файла, серверная отложка), а клавиатуру добавить бот
   правкой. Пост при этом выглядит обычным: ни плашки «переслано»,
   ни пометки «изменено».
2. **Право «изменять сообщения» у бота обязательно** — без него схема
   не работает. Это дополнительное требование к каналу сверх права
   публиковать.
3. **Кнопок не будет до публикации.** Отложенную запись бот не видит
   и не правит, поэтому у отложенного поста кнопки появляются только
   после выхода — когда приложение об этом узнает.
4. **Правя пост с кнопками, бот обязан передавать клавиатуру заново** —
   иначе она пропадёт.
5. **Пересылка не годится для «чистого» поста:** либо кнопки с плашкой
   «переслано», либо чистая копия без кнопок. Третьего пересылка не даёт.
   Причина логичная: копия без автора — это новое сообщение **от
   пользователя**, а такое кнопок нести не может.
6. **Копирование ботом даёт и то, и другое.** Бот копирует пост
   со склада (служебного канала) и прикладывает свою клавиатуру: копия
   чистая, кнопки с первой секунды, файл любого размера — перезаливки
   нет, лимит 50 МБ действует только на заливку. Цена: отправляет бот,
   значит время держит приложение (отложек у бота не бывает).
7. **Альбом с кнопками невозможен** — ни отправкой (у метода нет такого
   параметра), ни правкой (Telegram отбрасывает разметку
   у сгруппированных сообщений).
8. **Правило «кто правит» — разное у канала и группы** (проверено):
   - **в канале** администратор с правом «изменять сообщения» правит
     **любые** посты: и бот чужие, и пользователь чужие;
   - **в группе** такого права не существует, и каждый правит **только
     своё**: бот не может тронуть сообщение пользователя, пользователь —
     сообщение бота.

   Отсюда: в группе схема «бот дорисовывает кнопки» неприменима, кнопки
   возможны лишь у сообщений, отправленных самим ботом, и править такой
   пост потом может только бот.
9. **Вложение у вышедшего поста заменяется** публикателем, и кнопки
   при этом сохраняются; менять тип вложения (видео → фото) тоже можно.
   У отложенной записи вложение тоже заменяется.
10. **Любая правка ботом должна нести клавиатуру заново** — это касается
   не только текста, но и замены вложения: без неё кнопки исчезают.
11. **Снять кнопки может только бот** (передав пустую разметку).
   Публикатор не властен над разметкой ни в одну сторону: его правка
   её не трогает, а снять её он не может.

## Чего опыт не проверял

- **Кнопки с обратным вызовом** (`callback_data`): нажатие приходит боту,
  и бот обязан ответить, иначе у читателя крутится ожидание. Для
  приложения, которое запускается по надобности, это плохой выбор.
- Кнопки **отдельным сообщением после альбома** — обходной путь для
  альбомов; в опыте не проверялся.
- Судьбу кнопок при **удалении бота** из канала или потере им права
  правки (ожидаемо: уже поставленные кнопки остаются, новые не появятся).
- Кнопки в **теме форума** — механика та же, но живой пробы не было:
  тестовая группа не форум. Риск низкий.

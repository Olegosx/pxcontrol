# Модуль «Расписание» (отложенные записи)

> Статус: 🟢 реализовано (чтение) · Обновлено: 2026-08-15 · Владелец: olegosx

## Назначение

Показ отложенных записей всех активных каналов. **Своего планировщика
в приложении нет** ([ADR-0010](../02-architecture/decisions/0010-posts-fire-and-forget.md)):
отложенную запись создаёт публикация (`schedule_date` через userbot),
а хранит и публикует её **сервер Telegram** — приложение и компьютер
могут быть выключены.

## Как работает

- Страница «Расписание» читает отложенные записи из Telegram
  (`getScheduledHistory`): источник истины — сам канал, локальной
  таблицы постов нет. Опрашиваются только включённые каналы
  с userbot-админом (у бот-канала отложенных быть не может —
  Bot API их не умеет); ошибка одного канала не роняет список,
  канал пропускается с предупреждением в логе.
- Список перечитывается при каждом открытии страницы и кнопкой
  «Обновить»; фильтр-чекбоксы по каналам скрывают карточки,
  не меняя загруженного списка.
- Править и удалять отложенные можно из любого клиента Telegram.
- Создание постов — на странице «Публикация»
  ([ADR-0011](../02-architecture/decisions/0011-publish-via-userbot.md)).
- Отправка идёт через **персистентную очередь движка** (`PublishQueue`,
  [ADR-0016](../02-architecture/decisions/0016-persistent-publish-queue.md)):
  «Отправить» ставит пост в хвост и сразу освобождает форму; посты
  уходят последовательно, очередь видна на странице (статус, прогресс
  загрузки, «Отмена» у каждого элемента) и переживает перезапуск
  приложения. Telegram ограничивает отложки **100 на канал** (Premium
  лимит не увеличивает; горизонт — год): посты сверх лимита ждут
  в очереди со статусом «ждёт слота» и уходят по мере освобождения
  слотов (проверка раз в N минут, настройка) — **только при запущенном
  приложении**; первым внутри канала уходит ближайший по дате,
  просроченный публикуется сразу обычным сообщением. На странице —
  ближайшие 20 карточек и сводка; кнопка «Вся очередь…» открывает
  полный живой список с сортировкой и фильтрами (статус, канал).
- **Пакетная отправка**
  ([ADR-0015](../02-architecture/decisions/0015-batch-publishing.md)):
  «Пакет из папки…» собирает черновики из всех видео готовой папки
  и раскладывает их время по стратегии (стандартные времена канала,
  «каждый день/раз в N дней в ЧЧ:ММ», «каждые N часов», «сейчас»);
  у стратегий по дням задаётся дата начала, а занятые слоты —
  совпадение по минуте с существующими отложками канала
  (`PostsService.scheduled_times`) — пропускаются. Каждая строка
  правится до постановки, дальше — та же очередь и то же серверное
  хранение отложек.

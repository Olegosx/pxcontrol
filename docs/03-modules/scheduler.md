# Модуль «Расписание» (отложенные записи и очередь отправки)

> Статус: 🟢 реализовано · Обновлено: 2026-09-15 · Владелец: olegosx
>
> Решения — [ADR-0010](../02-architecture/decisions/0010-posts-fire-and-forget.md)
> (отложенные хранит сервер Telegram), [ADR-0016](../02-architecture/decisions/0016-persistent-publish-queue.md)
> (очередь отправки), [ADR-0028](../02-architecture/decisions/0028-scheduled-posts-as-queue.md)
> (отложенные как очередь: правка на сервере, общий список карточек).

## Назначение

Страница «Расписание» отвечает на вопрос «что будет опубликовано
и когда» — и показывает это двумя списками одного вида. **Своего
планировщика в приложении нет**: отложенную запись создаёт публикация
(`schedule_date` через userbot), а хранит и публикует её **сервер
Telegram** — приложение и компьютер могут быть выключены.

## Два списка — две вкладки

| | **Отложено** | **Очередь** |
|---|---|---|
| Где живёт пост | на сервере Telegram | в приложении (таблица `publish_queue_items`) |
| Уйдёт ли при выключенном приложении | да — публикует сервер | нет — ждёт слота или отправки в приложении |
| Откуда список | обход включённых сообществ (`getScheduledHistory`) | состояние очереди движка |
| Обновление | при показе (не чаще раза в минуту), кнопкой «Обновить», после действия — одно сообщество | опрос по таймеру, пока вкладка видна |
| Статус, прогресс | нет | есть (каркас заданий, ADR-0025) |
| Действия у карточки | «Сейчас», «Удалить», правка текста и времени | «Отмена», «Повторить», «Убрать», правка поста |
| Сортировка | ближайшие / по сообществам | + порядок постановки |
| Фильтры | сообщество, слот времени | + статус |

Разница неочевидна и важна, поэтому под заголовком страницы она
написана одной строкой. Всё остальное у списков одно: карточка
с логотипом сообщества и цветной меткой слота в шапке, подпись
«сообщество · публикация: когда · …», раскрытие кликом в форму
правки, страницы по 50, итоговая строка и перелистывание.

## Вкладка «Отложено»

- **Чтение.** Опрашиваются только включённые сообщества с userbot
  (у бот-сообщества отложенных быть не может — Bot API их не умеет).
  Канал — аккаунтом-умолчанием (отложки канала общие для админов),
  группа — **всеми участниками** (ADR-0022): отложку в группе видит
  только её создатель, подтверждено живым прогоном 2026-09-06.
  Ошибка одного опроса не роняет список — сообщество пропускается,
  подробности уходят в лог.
- **Неполный список честно назван неполным.** Движок возвращает
  записи и названия сообществ, которые прочитать не удалось
  (`ScheduledList.unread`), и страница пишет об этом над списком.
  Иначе пустой список читался бы как «отложенных нет», хотя часть
  сообществ просто не спросили, — а истина живёт на сервере.
- **Обход не дублируется и не повторяется зря.** Свежий список
  (моложе минуты) при показе не перечитывается; пока обход идёт,
  второй не начинается. Праздное листание вкладок ставило бы обходы
  один поверх другого, а флуд-лимит, пойманный на обходе, замораживает
  дорожку аккаунта целиком (ADR-0024) — ждать его будет уже публикация.
  Кнопка «Обновить» перечитывает всегда: это явная воля человека.
- **Адрес записи — тройка** `ScheduledRef`: сообщество, аккаунт, чьим
  чтением запись попала в список (в группе править может только
  создатель), id записи в очереди отложенных (он уникален внутри
  сообщества и не совпадает с id в ленте после публикации). Дубли
  от нескольких читателей схлопываются по id, а не по «текст + время»:
  два одинаковых поста — два поста.
- **Правка.** Клик по карточке раскрывает форму; запись читается
  **с сервера целиком** (`PostsService.scheduled_draft`) — её могли
  поправить из другого клиента, снимку списка верить нельзя. Правятся
  текст (у записи с вложением — подпись; предел длины по Premium
  аккаунта-читателя, счётчик под полем) и момент публикации
  (не ближе минуты). Вложение и тема форума показаны сноской
  и не правятся: у `messages.editMessage` нет адресата темы, а замена
  файла — загрузка с прогрессом, то есть задание очереди, а не правка;
  такую запись удаляют и создают заново на «Публикации». Переключатель
  «сейчас» в форме выключен с подсказкой: для этого у карточки кнопка.
- **«Сейчас» и «Удалить»** — с подтверждением, оба необратимы:
  первое отправляет запись в ленту немедленно
  (`messages.sendScheduledMessages`), второе снимает её, не публикуя
  (`messages.deleteScheduledMessages` — обычное удаление сообщений
  для очереди отложенных не годится).
- **После действия перечитывается только затронутое сообщество**
  (`list_scheduled(community_id)`), а не весь обход, — и после
  удачного, и после отказа: записи могло уже не быть (опубликована
  или удалена с телефона), и тогда карточка должна исчезнуть, а не
  остаться с кнопками в никуда. Исчезнувшая запись — `ScheduledGoneError`,
  штатная гонка с сервером-истиной.
- **Вложения не наших видов** (опрос, геопозиция — поставлены
  отложенными из клиента Telegram) читаются как `MediaKind.OTHER`:
  карточка их показывает, правится только время.
- Переход с дашборда («Расписание» на карточке сообщества) открывает
  вкладку с фильтром по этому сообществу — без нового обхода, если
  список свежий.

## Вкладка «Очередь»

Полный живой список очереди отправки — прежнее окно «Вся очередь…»
целиком: сортировка (ближайшие / порядок постановки / по сообществам),
фильтры по статусу, сообществу и слоту, страницы по 50, правка поста
в раскрытой карточке ([ADR-0016](../02-architecture/decisions/0016-persistent-publish-queue.md),
п. 6–7). Опрос движка идёт только пока вкладка видна. Сюда ведут
кнопки «Вся очередь…» на «Публикации» (там — ближайшие 20 карточек
и сводка) и на странице сообщества (фильтр по нему), действие
«Очередь» карточки дашборда (фильтр по сообществу) и плашка «N ошибок»
сводки дашборда (фильтр «ошибки»).

Сама очередь — [ADR-0016](../02-architecture/decisions/0016-persistent-publish-queue.md):
«Отправить» ставит пост в хвост и сразу освобождает форму; посты уходят
последовательно, очередь переживает перезапуск. Telegram ограничивает
отложки **100 на канал** (Premium лимит не увеличивает; горизонт — год):
посты сверх лимита ждут в очереди со статусом «ждёт слота» и уходят
по мере освобождения слотов (проверка раз в N минут, настройка) —
**только при запущенном приложении**; первым внутри канала уходит
ближайший по дате, просроченный публикуется сразу обычным сообщением.

**Пакетная отправка** ([ADR-0015](../02-architecture/decisions/0015-batch-publishing.md)):
«Пакет из папки…» собирает черновики из всех видео готовой папки
и раскладывает их время по стратегии (стандартные времена канала,
«каждый день/раз в N дней в ЧЧ:ММ», «каждые N часов», «сейчас»);
занятые слоты — совпадение по минуте с существующими отложками канала
(`PostsService.scheduled_times`) — пропускаются. Каждая строка
правится до постановки, дальше — та же очередь и то же серверное
хранение отложек.

## Устройство

- `engine/services/posts.py` — `list_scheduled`, `scheduled_draft`,
  `edit_scheduled`, `send_scheduled_now`, `delete_scheduled`,
  `ScheduledRef`/`ScheduledPostDto`/`ScheduledDraft`, `ScheduledGoneError`.
- `engine/telegram/mtproto.py` — `get_scheduled`, `get_scheduled_message`,
  `edit_scheduled`, `send_scheduled_now`, `delete_scheduled`,
  `media_kind_of` (вид вложения по типам Telethon).
- `ui/pages/schedule.py` — страница с вкладками; `ui/pages/scheduled_panel.py`
  — панель отложенных (`ScheduledPanel`, правило показа
  `apply_scheduled_view`, слияние `merge_community`);
  `ui/pages/scheduled_edit.py` — форма правки; `ui/pages/publish_queue_view.py`
  — вкладка очереди (`QueueViewTab`, `apply_view`); общие слои —
  `ui/pages/card_list.py` (список карточек), `ui/pages/list_view.py`
  (сортировки, фильтры, страницы, `ViewBar`, `PagerRow`),
  `ui/pages/queue_panel.py` (панель очереди).
- Та же панель отложенных работает на вкладке «Отложено» страницы
  сообщества — компактными карточками ([communities.md](communities.md)).

## Будущее

- Замена вложения у отложенной записи — как задание очереди
  с прогрессом (ADR-0028, альтернативы), если понадобится.
- APScheduler ([ADR-0004](../02-architecture/decisions/0004-apscheduler-tasks.md))
  вернётся в проект вместе с регулярными задачами парсинга источников —
  к публикации постов он отношения больше не имеет.

# Правила Telegram для имён файлов при загрузке

> Статус: 🟢 готов (вычислено опытным путём) · Обновлено: 2026-08-10 · Владелец: olegosx

## Назначение документа

Зафиксировать, как **сервер Telegram** изменяет имя файла при загрузке
медиа (имя из атрибута `DocumentAttributeFilename`). Эти правила нигде
не документированы официально — вычислены экспериментом: 57 проб
с userbot в «Избранное» (крошечное видео, имя задавалось атрибутом,
сохранённое имя читалось из ответа сервера и перепроверялось повторным
запросом). Скрипты проб и сырые данные — `_misc/tg_name_probe*.py` /
`*_results.txt` (папка вне git). Дата опыта: 10.08.2026.

Важно приложению: если собранное шаблоном имя длиннее порога, Telegram
молча изменит его — скачанный обратно файл будет называться иначе, чем
отправленный.

## Порог срабатывания

- Имя разбирается как «стем + последнее расширение» (`стем.mp4`).
- **Стем ≤ 78 символов Юникода — имя сохраняется байт в байт**
  (кроме управляющих символов, см. ниже). Стем ≥ 79 — включаются
  обрезка и чистка символов.
- Длина расширения на порог не влияет (проверено `.mp4` и `.webm`:
  полное имя из 83 символов с `.webm` уцелело, с `.mp4` — нет).
- Счёт — в **символах Юникода** (кодовых точках), не в байтах и не
  в парах UTF-16: кириллический стем из 78 букв (156 байт UTF-8) цел;
  латинский из 79 (79 байт) — обрезан; 40 эмодзи (80 пар UTF-16) целы.

## Что происходит с длинным именем (стем ≥ 79)

Порядок: сначала чистка символов, потом обрезка (удалённые символы
подтягивают хвост в сохраняемое окно).

1. **Чистка символов** в стеме:
   - удаляются целиком: `(` `)` `[` `]` `?` `~`
   - заменяются на `_`: пробел, дефис `-`, точка `.` (внутренние точки
     стема; расширение не трогается)
   - сохраняются: буквы любых алфавитов, цифры, эмодзи и символы
     ``, @ # & + ' ! = " : ; * % ^ $ _ { } / \ | < > « » № — …``
     и обратная кавычка (`` ` ``)
2. **Обрезка стема до 63 символов**; 64-й остаётся, только если ровно
   на нём заканчивается «слово» (64-й — буква/цифра, 65-й —
   разделитель). Многоточие не добавляется, расширение сохраняется.

## Замены независимо от длины (и в коротких именах)

- Табуляция, возврат каретки (CR), NUL, ESC → пробел.
- Перенос строки (LF) — сохраняется (особенность сервера).
- Все остальные символы в коротких именах (стем ≤ 78) не трогаются:
  скобки, дефисы, точки, `?`, `~` и пробелы целы.

## Прочее

- Отправка «как видео» и «как документ» (`force_document`) ведут себя
  одинаково.
- Правила одинаковы при чтении имени из ответа на отправку и при
  повторном чтении сообщения (проверялось каждой серией).

## Пример

Имя типовой структуры конвейера pXcontrol — «название,@канал,теги»
(в пробах участвовало реальное имя той же структуры с теми же длинами
всех частей — позиции среза совпадают). Отправлено (стем 94 символа):

```
WinterMorningLights,@nature_docs,4K,8K,Sunrise,Mountain,Twilight,Sunsets,Wildlife,Lake,Meadows.mp4
```

Сохранит сервер (стем 64 — «слово» кончилось ровно на 64-м символе,
запятые уцелели, чистить было нечего):

```
WinterMorningLights,@nature_docs,4K,8K,Sunrise,Mountain,Twilight.mp4
```

## Вывод для приложения

Чтобы имя пережило Telegram без изменений, **стем собранного имени
должен укладываться в 78 символов Юникода** и не содержать управляющих
символов. Предел рендера имени `MAX_FILENAME_BYTES` (240 байт UTF-8) —
про файловую систему; для Telegram он слишком щедрый.

Применено в `CaptionsService.render_filename`
(`TELEGRAM_MAX_STEM_CHARS` = 78): стем режется до конца последнего
законченного слова, без висячих знаков препинания; сплошное слово
без разделителей — как есть (см. [Подписи](captions.md)).
